# 몸의 발명사 전체 워크플로

## GitHub 지침 변경 게이트

사용자의 영구 수정 지시는 대화 메모가 아니라 이 저장소가 단일 원본이다. 다음 순서를 한 덩어리로 실행한다.

1. 수정 지시를 `episode_specific` 또는 `series_rule`로 분류한다.
2. `series_rule`은 `.codex/skills/timemedic/SKILL.md`와 직접 관련된 reference·validator에 반영한다.
3. 기존 규칙과 충돌하면 최신 명시 지시를 남기고 폐기된 규칙을 제거한다.
4. `python scripts/pipeline.py validate --all`로 저장소와 lock을 검증한다.
5. 변경 파일만 커밋하고 원격 `main`으로 푸시한다.
6. 원격 커밋 해시가 확인되어야 새 규칙이 `active`다. 푸시 실패 상태는 `rule_change_unpushed`이며 다음 유료 생성·게시보다 먼저 해결한다.

대용량 생성 파일은 Git에 넣지 않는다. 대신 정확한 로컬 상대 경로, 바이트 수, 길이, SHA-256, 생성 공급자·모델·계정 라우팅·시간을 receipt와 stage lock에 기록해 커밋한다.

### 편성 우선순위 예외

- `config/topic-source-100.txt`와 `topic_id`의 원본 번호는 바꾸지 않는다.
- 사용자가 특정 주제를 다음 편으로 명시하면 `config/editorial-priority.json`에 근거와 시각을 기록하고 그 주제를 우선 제작한다.
- 이 예외는 사용자 승인 편성 변경이다. 사이의 미완료 주제를 완료 처리하거나 삭제하지 않는다.
- 제품·브랜드 편만 연속으로 몰지 않고 전염병·공중보건·수술·진단·위생사를 교차 편성한다.
- 승인 대본의 최종 TTS가 `180.000초 초과`면 정보를 억지로 삭제하지 않고 `16:9 longform`으로 전환한다. `180.000초 이하`만 `9:16 Shorts`로 유지한다.

썸네일의 카피·주 피사체·공간 배치·최종 타이포 픽셀·모바일 QA·무문자 시작 이미지를 모두 06에서 잠근다. 첫 Flow 훅은 무문자 시작 이미지를 I2V 입력으로 사용하고, 최종 편집은 승인된 타이포 픽셀을 0초에 정확히 재합성한 뒤 길이·자막·첫 훅 동기화를 다시 검사한다.

## 핵심 불변식

1. 승인 대본의 SHA-256이 모든 후속 단계의 기준이다.
2. 문장 하나가 의미 장면 하나를 소유한다.
3. 최종 TTS 강제정렬이 장면·자막·카메라·오버레이의 유일한 시간축이다.
4. 기본 영상 엔진은 Google Flow `Omni Flash`, `9:16`, `8초`, `x1`이다. 첫 훅만 승인 무문자 이미지 기반 `Image to Video`, 나머지는 `Text to Video`이며 Quality는 사용하지 않는다.
5. 영상 생성 공급자는 Google Flow 하나다. Seedance·Runway·Higgsfield 등 외부 엔진으로 자동 전환하지 않으며, Flow가 보안·가용성·크레딧 사유로 막히면 같은 단계에 blocker를 남기고 Flow에서 재개한다.
6. 기본 비주얼은 한국 의학 박물관의 무광 수제 레진 디오라마다. 실사 배우, 유광 장난감, 치비, 생성 글자는 불합격이다.
7. 생성 원본 8초 전체를 쓰지 않고 문장에 맞는 1–3초 행동만 수확한다.
8. 최종 영상과 TTS 길이는 최대 1프레임만 차이 날 수 있다.
9. 최종 QA와 `final-sync.lock.json=PASS` 전에는 업로드하지 않는다.

## 대본

- 사용자의 수정본을 먼저 그대로 보존하고, 왜 고쳤는지 문장 기능을 분석한 뒤에만 제안본을 만든다.
- 제품 편 도입은 익숙한 물건을 함께 바라보기→생활 기억→감각 행동→역사적 빈칸 질문의 순서를 쓴다.
- 새 인물은 역할과 문제의 관계를 설명한 뒤 이름을 말한다.
- `왜 필요했나→당시 무엇을 해야 했나→왜 느렸나→무엇을 바꿨나→실제 행동→누가 확산했나`가 모두 있어야 한다.
- 숫자는 TTS용 한글과 화면용 숫자를 같은 사실값에서 따로 만든다.
- `~니다`와 `~죠`를 각각 3회 연속 쓰지 않는다. 접속사는 장면 장식이 아니라 원인·대조·시간 연결에 사용한다.

## Flow 생성

- 영상 생성은 Flow 전용이다. 외부 영상 엔진 fallback은 없으며 Flow 제한 중 다른 Flow 입력 경로로 바꾸어 제출을 계속하지 않는다.
- 같은 Google 계정을 쓰는 다른 Codex 작업이나 Flow 프로젝트가 생성 중이면 새 요청을 겹쳐 보내지 않는다. 계정 전체에서 활성 생성은 하나다.
- 한 번에 활성 생성은 하나다. 이전 후보가 완료/실패하고 저장·QA까지 끝난 뒤 다음 요청을 보낸다.
- Flow 프롬프트는 실제 연속 키 입력으로만 넣는다. 붙여넣기, `fill`, DOM 주입은 금지한다.
- 긴 프롬프트는 `pressSequentially`로 8–16자씩 입력하고 매 청크 뒤 현재 문자열이 잠긴 프롬프트의 정확한 접두사인지 확인한다. 비교할 때 끝 공백을 `trim`하면 같은 공백이 중복 입력될 수 있으므로 줄바꿈·제로폭 문자만 제거하고 일반 공백은 보존한다. 입력 타임아웃이 나도 바로 초기화하지 않고 실제 보존된 접두사 길이부터 이어간다.
- 생성 직전 입력창 전문과 생성 직후 새 카드의 서버 반영 전문을 잠긴 프롬프트와 각각 비교한다. 새 카드가 한 글자나 일부 문장만 보존했으면 그 결과는 폐기하고 `invalid_prompt_persistence`로 기록한다.
- 생성 클릭 뒤 최소 180초, terminal 뒤 추가 60초 중 더 늦은 시각을 따른다.
- 연속 세 건 뒤 10분 동안 새 생성을 쉬고 수확·정렬·편집만 한다.
- 상태가 불명확하면 다시 누르지 않고 `status_unknown`으로 잠근다.
- 비정상 활동·보안 확인·CAPTCHA가 보이면 즉시 멈추고 blocker를 남긴다.
- 비정상 활동의 24시간 재발 판정은 최소 대기 뒤 **새로 제출한 한 건**이 같은 경고로 실패했을 때만 한다. 과거 실패 카드가 화면에 남아 있는 것은 현재 계정 제한의 증거가 아니다. 다른 프로젝트가 정상 로드되고 최근 생성 결과를 읽을 수 있으면 동시 활성 요청 0건을 확인한 뒤 실패 단위 하나만 직렬 재시도한다.
- 네이티브 오디오는 화면 사건과 2프레임 이내로 맞을 때만 살리고, 가짜 대사·음악·공간 불일치가 있으면 음소거 후 교체한다.

## TTS·자막·편집

- 보이스는 에피소드 lock에 적힌 선택을 사용한다. 다른 음성이나 구버전 음성으로 대체하지 않는다.
- 승인 대본이 바뀌면 TTS를 처음부터 새로 생성한다.
- 기본은 승인 대본 전체를 한 번에 합성한다. 공급자 길이 제한이 있을 때만 이야기 흐름이 유지되는 큰 구간 최대 3개로 나누며, 문장별·한두 문장별 생성물을 이어 붙이지 않는다.
- 분할 경계는 같은 음성·모델·속도·감정 설정으로 만들고 음색·속도·호흡 점프를 전부 청취 검수한다. 하나라도 튀면 전체 또는 해당 큰 구간을 다시 합성한다.
- 자막은 `Gmarket Sans Bold 100px`, 검정 외곽선 `30px`, 그림자, 중심 `x=540 y=1200`이다.
- 자막 페이지는 2–4어절이며 강제정렬 단어의 실제 시작·끝을 사용한다.
- 썸네일은 공백 제외 전체 10글자 이하의 두 블록을 `상단 전제 / 하단 핵심어`로 크게 분리한다. `Gmarket Sans Bold`, 상단 흰색·하단 노란색, 바깥 흰색 30px·안쪽 차콜 14px·깊은 검정 그림자를 사용하며 최종 영상의 0초 실제 프레임이다.
- 카메라와 오버레이는 `발화→타임코드→의미 대상→앵커→카메라→반응→사운드→인과 목적`을 모두 가져야 한다.
