## 핵심 불변식

1. 승인 대본의 SHA-256이 모든 후속 단계의 기준이다.
2. 문장 하나가 의미 장면 하나를 소유한다.
3. 최종 TTS 강제정렬이 장면·자막·카메라·오버레이의 유일한 시간축이다.
4. 기본 영상 엔진은 Google Flow `Omni Flash`, `Text to Video`, `9:16`, `8초`, `x1`이다. Quality는 사용하지 않는다.
5. 기본 비주얼은 한국 의학 박물관의 무광 수제 레진 디오라마다. 실사 배우, 유광 장난감, 치비, 생성 글자는 불합격이다.
6. 생성 원본 8초 전체를 쓰지 않고 문장에 맞는 1–3초 행동만 수확한다.
7. 최종 영상과 TTS 길이는 최대 1프레임만 차이 날 수 있다.
8. 최종 QA와 `final-sync.lock.json=PASS` 전에는 업로드하지 않는다.

## 대본

- 사용자의 수정본을 먼저 그대로 보존하고, 왜 고쳤는지 문장 기능을 분석한 뒤에만 제안본을 만든다.
- 제품 편 도입은 익숙한 물건을 함께 바라보기→생활 기억→감각 행동→역사적 빈칸 질문의 순서를 쓴다.
- 새 인물은 역할과 문제의 관계를 설명한 뒤 이름을 말한다.
- `왜 필요했나→당시 무엇을 해야 했나→왜 느렸나→무엇을 바꿨나→실제 행동→누가 확산했나`가 모두 있어야 한다.
- 숫자는 TTS용 한글과 화면용 숫자를 같은 사실값에서 따로 만든다.
- `~니다`와 `~죠`를 각각 3회 연속 쓰지 않는다. 접속사는 장면 장식이 아니라 원인·대조·시간 연결에 사용한다.

## Flow 생성

- 한 번에 활성 생성은 하나다. 이전 후보가 완료/실패하고 저장·QA까지 끝난 뒤 다음 요청을 보낸다.
- 생성 클릭 뒤 최소 180초, terminal 뒤 추가 60초 중 더 늦은 시각을 따른다.
- 연속 세 건 뒤 10분 동안 새 생성을 쉬고 수확·정렬·편집만 한다.
- 상태가 불명확하면 다시 누르지 않고 `status_unknown`으로 잠근다.
- 비정상 활동·보안 확인·CAPTCHA가 보이면 즉시 멈추고 blocker를 남긴다.
- 네이티브 오디오는 화면 사건과 2프레임 이내로 맞을 때만 살리고, 가짜 대사·음악·공간 불일치가 있으면 음소거 후 교체한다.

## TTS·자막·편집

- 보이스는 에피소드 lock에 적힌 선택을 사용한다. 다른 음성이나 구버전 음성으로 대체하지 않는다.
- 승인 대본이 바뀌면 TTS를 처음부터 새로 생성한다.
- 자막은 `Gmarket Sans Bold 100px`, 검정 외곽선 `30px`, 그림자, 중심 `x=540 y=1200`이다.
- 자막 페이지는 2–4어절이며 강제정렬 단어의 실제 시작·끝을 사용한다.
- 썸네일은 `Gmarket Sans Bold 175px`, 검정 외곽선 30px, 그림자이며 최종 영상의 0초 실제 프레임이다.
- 카메라와 오버레이는 `발화→타임코드→의미 대상→앵커→카메라→반응→사운드→인과 목적`을 모두 가져야 한다.
