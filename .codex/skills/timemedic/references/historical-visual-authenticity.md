# 몸의 발명사 시대·지역·제품 고증 및 시각화 계약

## 1. 프롬프트 전에 고증 카드를 잠근다

스토리보드 직후, Flow 생성 계획 전에 `plans/historical-authenticity-card.json`을 만든다. 한 편에 시대가 여러 개면 시대 구간별 카드를 만든다.

필수 필드:

```text
era_segment_id
date_range
region_and_city
political_and_social_context
people_ethnicity_and_roles
wardrobe_hair_and_protective_gear
architecture_and_interior
street_harbor_hospital_or_lab_layout
lighting_sources
tools_containers_and_medical_devices
materials_and_manufacturing
transport_and_infrastructure
climate_season_and_environment
forbidden_anachronisms
source_ids
visual_anchor_en
negative_anchor_en
```

- 연도만 적고 끝내지 않는다. 그 시대 사람이 실제로 서 있을 바닥, 벽, 창문, 조명, 옷, 그릇, 수레, 배, 병원·실험실 구조까지 잠근다.
- 한 장면에 서로 다른 시대·지역이 섞이지 않게 `era_segment_id`를 모든 스토리보드 장면과 생성 단위에 연결한다.
- `visual_anchor_en`과 `negative_anchor_en`은 해당 시대의 모든 Flow 프롬프트에 글자 그대로 복사한다. 요약·생략하면 실패다.
- 자료가 충돌하면 확정처럼 그리지 않는다. 불확실한 부분은 넓은 시대 범위의 검증된 공통 요소로 낮추고 카드에 불확실성을 적는다.

## 2. 역사 장면 하드 실패

다음이 한 프레임이라도 핵심 배경에 보이면 해당 후보를 폐기한다.

- 시대에 없는 콘크리트, 강철 빔, 형광등, 네온, 현대 유리창, 플라스틱, 현대 병상·의료기기·도로 표지.
- 지역과 다른 인종·복식·머리 모양·종교 건축·문양·선박·가구를 대표 장면처럼 사용.
- 중세 항구인데 빅토리아풍 거리, 대한제국 약방인데 중국풍 궁전처럼 서로 다른 문화권을 혼합.
- 역사 인물이 실사 배우나 현대 광고 모델처럼 보이는 장면.
- 생성 모델이 만든 읽을 수 있는 한글·로고·연도·제품 라벨.

현대 회수 장면은 `modern_segment`로 분리하고, 역사 장면의 배경 소품이 되지 않게 한다.

## 3. 실재 제품 고증

제품·브랜드 탄생사는 공식 제조사·박물관·등록 자료의 시대별 제품 컷을 우선한다.

- 제품명, 용기, 마개, 라벨, 용량, 색, 포장 형태, 출시 연도별 차이를 `registered_product_form`에 기록한다.
- 공식 URL, 확인일, source_id, 로컬 파일 SHA-256을 잠근다.
- 생성 모델에 상표·라벨을 다시 그리게 하지 않는다. 무문자 용기 또는 디오라마 세트를 만들고, 공식 권리 검토를 통과한 제품 컷만 식별 용도로 합성한다.
- 현재 제품을 과거 장면에 놓거나, 과거 용기를 현재 제품처럼 말하지 않는다.
- 제품 팩샷이 없으면 유사 가짜 라벨을 만들지 말고 용기 구조·제조 행동 중심으로 설명한다.

## 4. 몸과 치료의 작동을 해부한다

각 문장에서 먼저 다음 다섯 단계를 작성한다.

1. 등장하는 사람·병원체·기관·도구·물질·제도를 모두 나열한다.
2. 실제 움직이는 대상과 방향을 쓴다.
3. 원인→전달→몸의 반응 또는 조치→결과의 경로를 쓴다.
4. 겉에서 이해되지 않으면 `CUTAWAY`, 부품 관계가 핵심이면 `EXPLODED`, 힘·흐름이 핵심이면 `MECHANISM`으로 올린다.
5. 그 문장의 시각적 주인공 하나를 고른다.

건강 역사형 5단계 시각 체인:

1. `L1 CONTEXT`: 시대·도시·병원·가정의 전체 맥락.
2. `L2 APPROACH`: 사람·도구·병원체·제품으로 접근.
3. `L3 CUTAWAY`: 몸·용기·건물·선박·제도의 단면.
4. `L4 EXPLODED`: 도구·약물·방역 단계의 부품과 역할 분리.
5. `L5 MECHANISM`: 압력·혈류·감염·약물·격리 경로를 화살표·입자·흐름으로 설명.

- 작동 해부 챕터에는 L3→L4→L5를 모두 넣는다.
- 겉모습 컷이 세 개 연속되면 실패다.
- L5 뒤에는 L1 또는 L2로 빠져나와 사람에게 어떤 변화가 생겼는지 보여준다.
- 단면과 원리 설명은 분위기보다 판독성이 우선이다. 내부가 어두우면 실패다.
- 정확한 글자·숫자·방향선은 후반 렌더러에서 얹는다. Flow에는 빈 표찰과 시각적 흐름만 요청한다.

## 5. 살아 움직이는 카메라 계약

- 정지 카메라는 전체의 20% 이하만 허용한다.
- 20~25개 생성 단위당 `THROUGH` 관통 카메라를 최소 네 번 사용한다. 장편은 생성 단위 여섯 개당 한 번 이상으로 비례한다.
- 같은 카메라 이동을 두 단위 연속 사용하지 않는다.
- 장면마다 손·물체·액체·입자·군중·카메라 중 하나의 `motion_carrier`가 있어야 한다.
- 1.5~2.5초마다 새 시각 정보가 생기되 현재 문장의 의미 안에서만 움직인다.
- 앞뒤 장면은 피사체·이동 방향·화면 위치·카메라 축 가운데 둘 이상을 공유하고 행동 매치·물체 매치·가림·휩팬·벽/피부/용기 관통 중 하나로 연결한다.
- 컷 전환 때 화면 전체가 이유 없이 떠는 후보는 폐기한다. 흔들림으로 속도감을 대신하지 않는다.

`THROUGH`는 장식이 아니다. 피부 밖에서 몸속, 항구 밖에서 검역 섬, 약병 밖에서 제조·작동 원리처럼 `겉의 질문 → 속의 답`으로 이동할 때 사용한다.

## 6. Flow 프롬프트 컴파일 순서

각 단위의 영어 프롬프트는 아래 순서를 지킨다.

1. 고정 디오라마 스타일 앵커.
2. 해당 `visual_anchor_en` 전문.
3. 시작 프레임의 사람·물체·공간 배치.
4. 보이는 물리 행동과 motion carrier.
5. 카메라 이동 한 가지.
6. 환경 반응과 보이는 사건의 native audio.
7. 종료 프레임과 다음 단위의 match anchor.
8. `negative_anchor_en` 전문과 생성 글자·대사·내레이션 금지.

첫 훅만 승인된 무문자 썸네일 이미지를 I2V로 이어 움직이고, 나머지는 T2V를 기본으로 한다. I2V에서는 시작 이미지의 형태를 다시 묘사하지 않고 움직임·카메라·환경만 쓴다.

## 7. 생성 전·후 검사

생성 전:

- 모든 장면에 `era_segment_id`와 source_ids가 있는가.
- 모든 프롬프트가 고정 시대 앵커·금지 앵커를 전문으로 포함하는가.
- 실재 제품 형태와 공식 컷이 잠겼는가.
- L3·L4·L5와 카메라 관통 쿼터가 계획에 들어갔는가.

생성 후:

- 시대·지역·복식·건축·도구가 실제 프레임에서 맞는가.
- 생성 글자·로고·제품 라벨·현대 소품이 없는가.
- 카메라 떨림 없이 시작·행동·종료 앵커가 보이는가.
- 정지 비율 20% 이하, 관통 쿼터, 같은 무빙 연속 0을 실제 후보에서 통과했는가.

프롬프트에 규칙이 적혀 있어도 화면이 틀리면 실패다.
