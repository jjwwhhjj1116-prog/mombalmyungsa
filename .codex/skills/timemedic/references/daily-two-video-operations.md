## 1. 목표와 불변식

- 원본 100개 주제를 번호 순서대로 처리해 50일 동안 하루 두 편을 목표로 한다.
- 조회수 100만은 목표이지 보증이 아니다.
- 순서를 조용히 건너뛰지 않는다. 검증 실패 주제는 `blocked`로 남기고 사용자의 대체·보류 결정 없이 다음 번호를 당겨 게시하지 않는다.
- 기존 CPR 편은 `pilot-000`으로 관리하며 100개 정규 큐에 합치지 않는다.
- 한 영상의 모든 16단계 잠금은 다른 영상과 독립적이다.
- 미검증 주제 제목은 아이디어일 뿐이다. 제목에 들어 있는 숫자, 최초, 인용, 효능, 인과관계는 `01_evidence_map`에서 다시 검증한다.

## 2. 50일 주제 큐

원본 번호 `2n-1`과 `2n`을 `DAY n`의 A·B 레인에 배정한다.

Git 단일 원본은 다음 세 파일이다.

- `config/topic-source-100.txt`: 사용자가 처음 준 주제 설명 원문
- `config/topic-catalog-100.json`: 검증 전 raw claim과 구조화된 topic ID
- `config/50-day-two-video-schedule.json`: 50일 A/B 레인, 업로드·공개 시각, idempotency key

로컬 outputs 폴더나 이전 채팅의 기억으로 큐를 재구성하지 않는다.

```text
DAY 01: 001 박카스 / 002 까스활명수
DAY 02: 003 우루사 / 004 안티푸라민
...
DAY 50: 099 표적항암제 / 100 mRNA 백신
```

큐는 `build_daily_topic_queue.py`로 생성한다. 각 항목은 원문을 보존하되 `verification_status=pending`, `publishable=false`로 시작한다. 실제 제작일에는 `init_daily_pipeline_day.py`로 해당 DAY의 A·B 두 매니페스트만 초기화한다.

## 3. 세 개의 롤링 작업일

매일 두 편을 안정적으로 내기 위해 제작과 게시를 같은 날 처음부터 끝까지 하지 않는다.

### D-2 조사·대본일

- `00_topic_discovery`부터 `05_script_approval`까지 진행한다.
- 두 레인을 각각 조사하고 사용자가 수정할 대본을 보여준다.
- 승인되지 않은 편은 D-1로 넘기지 않는다.

### D-1 영상 제작일

- `06_storyboard`부터 `13_semantic_motion_sound`까지 진행한다.
- 훅과 반전 파일럿을 먼저 승인받고 일괄 생성한다.
- TTS 강제정렬이 끝난 뒤에만 영상 컷을 확정한다.

### D0 검수·업로드일

- `14_final_qa`와 `15_packaging_release`를 진행한다.
- 통과한 첫 장면 위에 06에서 잠근 썸네일 카피·배치를 렌더하고 0초에 삽입한 뒤 길이·첫 훅·자막을 다시 검수한다.
- 공개 60분 전에 비공개 업로드한다.
- HD 처리, 자막, 제목, 설명, 썸네일, 의료 고지, 권리, 채널을 확인한 뒤 예약한다.
- 공개 시각에 공개 URL을 다시 확인해 publication lock을 만든다.
- 주제와 직접 관련된 실제 상품이 있으면 `commerce_route`를 평가한다. 검증·승인된 편만 쿠팡 링크 또는 YouTube Shopping 태그를 붙이고, 그렇지 않은 편은 본편을 비제휴 상태로 게시한다.

이 구조가 안정화되면 한 날짜에 `오늘 공개 2편`, `내일 제작 2편`, `모레 조사·대본 2편`의 최대 6개 에피소드가 서로 다른 단계에 있을 수 있다.

## 4. 두 제작 레인

- `lane_a`: 그날의 홀수 번호 주제.
- `lane_b`: 그날의 짝수 번호 주제.
- 같은 파일, 보이스 잠금, Flow 후보, idempotency key를 공유하지 않는다.
- 공통 스타일 프리픽스와 타이포만 공유한다.
- 레인 하나가 차단돼도 다른 레인의 제작·게시 조건이 모두 통과하면 다른 한 편은 진행할 수 있다.

## 5. 공개 슬롯

고정 공개 슬롯은 한국시간 11:00와 19:00이다.

- A편 비공개 업로드 10:00 → 처리·HD·자막·패키징 검수 → 11:00 공개 예약.
- B편 비공개 업로드 18:00 → 처리·HD·자막·패키징 검수 → 19:00 공개 예약.
- 이 시각 규칙은 2026-08-17 사용자 승인으로 `schedule_approved=true`다. 다만 각 편의 대본 승인·최종 QA·권리·정확한 채널 검증이 끝나지 않으면 해당 슬롯은 `blocked`로 남기고 자동 공개하지 않는다.

### Shorts와 longform 투트랙

- 최종 승인 대본을 최종 보이스·모델·속도로 전체 합성한 TTS 길이가 `180.000초 이하`면 `9:16 Shorts`로 제작한다.
- TTS 길이가 `180.000초 초과`면 대본을 억지로 줄이지 않고 `16:9 longform`으로 전환한다.
- 판정은 글자 수나 예상 낭독 시간이 아니라 실제 TTS 미디어 길이로만 한다. 대본·보이스·속도가 바뀌면 다시 판정한다.
- longform도 같은 A/B 공개 슬롯을 사용할 수 있지만 1920x1080 최종본, 별도 16:9 썸네일, longform 자막 안전영역과 업로드 유형을 각각 잠근다.
- 한 레인이 longform으로 전환돼도 다른 레인의 순서와 idempotency key를 바꾸지 않는다.

## 6. 차단과 재개

다음이면 게시하지 않는다.

- 핵심 반전이 공식·학술 근거로 확인되지 않음
- 제품 효능을 광고처럼 과장함
- 실제 인용문·숫자·최초 주장의 직접 출처가 없음
- 대본 사용자 승인 없음
- Omni 파일럿 승인 없음
- TTS 대본 동일성·강제정렬 실패
- 문장 종료 전 다음 의미 장면이 나옴
- 의료기구·손·신체 변형, 생성 글자, 고어가 남음
- 최종 QA, 권리검수, 정확한 YouTube 채널 확인 실패

차단 원인을 고친 뒤 같은 topic_id와 idempotency key를 이어 쓴다. 새 번호나 새 게시 잡으로 중복 우회하지 않는다.
