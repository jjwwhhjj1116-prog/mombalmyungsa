## 목적

주제만 정하면 곧바로 영상 생성으로 넘어가지 않는다. 각 단계는 입력, 산출물, 검수 기준, 잠금 파일을 가진다. 이전 잠금의 SHA-256이 없거나 검수에 실패하면 다음 단계와 유료 생성을 차단한다.

참고 튜토리얼에서 가져올 장점은 다음뿐이다.

- 소재를 먼저 여러 개 뽑고 시각적으로 강한 하나를 고른다.
- 대본과 영상 프롬프트를 분리한다.
- 한국어 프롬프트는 사람 검수용, 영어 프롬프트는 생성용으로 함께 관리한다.
- 한 컷을 통째로 쓰지 않고 후보 영상에서 좋은 부분만 수확한다.
- 최종 편집은 TTS 위에서 수행하고, 부족한 길이만 제한적으로 보간한다.

그대로 가져오지 않는 항목도 명확히 한다.

- Flow가 생성한 한글, 숫자, 화살표, 표찰은 쓰지 않는다. 빈 판을 만든 뒤 후반 렌더러에서 정확히 합성한다.
- 720p는 검수용 프록시에만 허용한다. 최종본은 1080x1920이다.
- 모든 생성 단위를 무조건 두 번 만들지 않는다. 훅, 반전, 복잡한 물리 행동, 인물 연속성처럼 실패 비용이 큰 단위만 후보 두 개를 먼저 만든다.
- 광학 흐름은 느린 장면을 꾸미는 효과가 아니다. 좋은 구간이 TTS보다 짧을 때만 쓰고, 손·얼굴·의료기구 변형 검사를 통과해야 한다.

## 00 주제 발굴 점수

후보마다 0–5점으로 평가한다.

- `present_familiarity`: 오늘 사람들이 아는 행동인가?
- `hidden_contradiction`: 당연함을 뒤집는 검증된 모순이 있는가?
- `visual_mechanism`: 몸속 과정과 발명 행동을 영상으로 보여줄 수 있는가?
- `human_stakes`: 실패했을 때의 손실이 구체적인가?
- `reversal_strength`: 질문을 바꾼 실제 행동이 있는가?
- `evidence_strength`: 공식·학술 근거가 충분한가?
- `current_relevance`: 현재 안전·건강 행동으로 돌아올 수 있는가?
- `originality`: 흔한 건강 상식 요약과 다른가?

`evidence_strength < 4`, `visual_mechanism < 3`, 의료 안전 문구를 만들 수 없는 주제는 총점과 무관하게 탈락시킨다. 최고점만 고르지 말고 상위 세 후보의 훅 한 문장까지 만든 뒤 최종 한 개를 잠근다.

## 03–05 대본 게이트

대본은 `현대 결과 → 당연함 속 모순 → 과거의 끔찍한 방식 → 두 선택 모두 손실 → 우연한 관찰 → 질문 전환 → 구체적 행동 → 검증된 결과 → 현재 의미`로 이어진다.

- 초등학생도 원리를 따라갈 수 있는 은유를 쓰되 사실을 왜곡하지 않는다.
- `~니다`, `~죠`, `~요`, 질문, 짧은 단정을 연기 목적에 맞게 섞는다.
- 자극적 표현은 긴장을 만들 때만 쓰고 의료 결과를 기적처럼 보장하지 않는다.
- 사용자가 수정한 말맛을 이중 검수에서 설명조로 되돌리지 않는다.
- 대본 승인이 없으면 스토리보드, 보이스 합성, Flow 유료 생성을 금지한다.

## 05.5 실제 TTS 길이 라우팅 게이트

- 05 대본 승인 직후 최종 보이스·모델·속도로 승인 대본 전체를 한 번 합성한다. 문장별 TTS 이어붙이기는 금지한다.
- `duration_seconds <= 180.000`이면 `content_format=shorts`, `aspect_ratio=9:16`, `render_size=1080x1920`으로 잠근다.
- `duration_seconds > 180.000`이면 `content_format=longform`, `aspect_ratio=16:9`, `render_size=1920x1080`으로 잠근다.
- `05-duration-route.lock.json`에는 TTS 파일·대본·보이스·모델·속도 해시, 실제 길이, 임계값, 선택 형식과 화면비를 기록한다.
- 이 잠금이 없으면 06 스토리보드와 07 Flow 계획은 provisional이며 유료 Flow 생성을 시작하지 않는다.
- 11단계는 같은 TTS에 강제정렬만 추가한다. 대본·보이스·속도가 바뀌면 05.5부터 화면비 의존 잠금을 다시 만든다.

## 06 문장별 스토리보드 계약

문장마다 다음 필드를 채운다.

```text
sentence_id
dialogue
scene_action
emotion
meaning_target
camera_purpose
continuity_in
continuity_out
match_anchor
motion_carrier
transition_mechanism
overlay_trigger
sound_trigger
```

한 문장 안에서 1–3개의 짧은 컷을 쓸 수 있지만 모두 같은 의미만 강화한다. 앞 문장의 `continuity_out`과 다음 문장의 `continuity_in`은 운동 방향, 피사체 위치, 물체, 조명 가운데 최소 하나를 공유해야 한다.

첫 문장은 추가로 `thumbnail_copy`, `thumbnail_visual_anchor`, `frame_zero_composition`, `frame_zero_camera_axis`, `first_motion_after_hold`를 가진다. 07 생성 계획 전에 카피·주 피사체·배치뿐 아니라 최종 타이포 픽셀, 모바일 축소 QA, 같은 구도의 무문자 시작 이미지까지 잠근다. 각 경로와 SHA-256은 `06-thumbnail.lock.json`에 기록하고, 하나라도 없거나 해시가 다르면 07과 Flow를 차단한다. 첫 Flow 훅은 무문자 시작 이미지를 I2V 입력으로 사용하고, 14단계에서는 승인 타이포 픽셀을 새로 디자인하지 않고 정확히 0초에 재합성해 다시 검수한다.

## 07–10 Omni 후보와 수확

### 생성 단위

- 인과적으로 붙은 2–3문장을 8초 멀티샷 한 단위로 묶고 모든 단위의 화면비는 `05-duration-route.lock.json`과 같아야 한다.
- 첫 훅 단위만 `06-thumbnail.lock.json`의 무문자 시작 이미지 SHA-256을 검증한 뒤 I2V로 만든다. 나머지 생성 단위는 Omni Flash T2V를 유지한다.
- 한국어 검수 프롬프트와 영어 생성 프롬프트를 함께 저장한다.
- 프롬프트에는 시작 프레임, 물리 행동, 카메라 이동, 환경 반응, 종료 프레임, 다음 장면 연결 앵커를 쓴다.
- 프롬프트에는 샷별 `motion_carrier`와 화면에서 실제로 날 물체음·공간음만 적은 `native_audio_plan`을 함께 쓴다.
- 생성 영상에는 내레이션, 대사, 정확한 글자, 숫자, 로고를 요구하지 않는다.
- 모든 단위는 [reference-channel-flow-grammar.md](reference-channel-flow-grammar.md)의 분석 문법을 적용한 `reference_grammar_lock`을 가져야 한다. 특정 참고 영상의 장면을 복제하지 않고 멀티샷, 문제 누적, 반전 직전 홀드, 의미 대상 카메라 이동, 현재 장면 회수만 채택한다.

### Flow 요청 속도와 이상 활동 보호

이 규칙은 플랫폼 제한을 우회하거나 탐지를 피하기 위한 것이 아니다. 중복 클릭과 과도한 병렬 요청을 막고 Flow가 한 작업을 정상 처리할 시간을 주는 로컬 요청 제한이다.

- 기본 생성은 `x1`이며 동시에 활성화할 수 있는 생성 작업은 정확히 하나다. 여러 탭·여러 프로젝트·여러 브라우저에서 병렬 생성하지 않는다.
- Flow의 Slate 입력창은 `fill`, DOM 주입, 시스템·가상 클립보드 붙여넣기를 화면에는 보여주면서 서버에는 일부만 반영할 수 있다. 생성 프롬프트는 실제 키 입력인 `pressSequentially` 계열로만 입력하며 붙여넣기 경로를 사용하지 않는다.
- `만들기` 직전에는 입력창 전체 문자열이 잠긴 영어 프롬프트와 바이트 단위로 같은지 검사한다. 클릭 뒤에는 프로젝트 목록의 새 생성 카드에 표시된 **서버 반영 프롬프트**가 잠긴 프롬프트와 다시 같은지 확인한다. 입력창 검사만으로 제출 성공을 판정하지 않는다.
- 서버 반영 카드가 한 글자·부분 문장·다른 프롬프트이면 결과가 정상 생성돼도 `invalid_prompt_persistence`로 폐기한다. 후보 ID와 실제 서버 반영 문자열을 blocker에 남기고, 속도 제한과 일반 실패 재시도 대기 시간을 모두 지킨 뒤 해당 단위만 키 입력으로 다시 제출한다.
- `만들기` 클릭 시각을 로그에 기록한다. 다음 유료 생성 클릭은 **이전 클릭 후 180초가 지났고**, 이전 후보가 완료 또는 실패로 확정된 뒤 **추가로 60초가 지났을 때**만 허용한다. 두 조건 중 더 늦은 시각을 따른다.
- 후보가 완료되면 다운로드, 미디어 프로브, 접점 시트 또는 프레임 QA, 후보 판정 로그까지 끝내고 다음 요청으로 간다. 생성 중 진행률이 보이면 실패 배지가 함께 보여도 다시 누르지 않는다.
- 연속 생성 세 건을 처리한 뒤에는 성공 여부와 관계없이 10분간 새 생성을 쉬고, 그동안 수확·TTS 정렬·편집·QA만 수행한다.
- 브라우저 제어 타임아웃이나 응답 지연이 생겨도 즉시 다시 클릭하지 않는다. 프로젝트 목록에서 후보 ID·진행률·크레딧 변화를 읽어 중복 요청 여부를 먼저 확인하고, 불명확하면 해당 단위를 `status_unknown`으로 잠가 새 생성을 중단한다.
- 일반 생성 실패가 확정되면 원인을 기록하고 15분 뒤 실패 단위 하나만 재시도한다. 같은 프롬프트를 연속 제출하지 않고 실패 원인에 필요한 최소 수정만 한다.
- `비정상적인 활동이 감지되었습니다`, 보안 확인, CAPTCHA 또는 계정 제한이 보이면 즉시 모든 생성을 중단한다. 같은 세션에서 재시도하지 않고 blocker를 남긴 뒤 최소 2시간 후 로그인 계정과 제한 해제 여부를 읽기 전용으로 확인한다. 다시 나타나면 24시간 동안 Flow 생성을 멈추고 사용자에게 알린다.
- 속도 제한 상태는 `last_submit_at`, `last_terminal_at`, `next_allowed_submit_at`, `consecutive_jobs`, `cooldown_reason`, `candidate_id`로 생성 로그에 보존한다. `next_allowed_submit_at` 전에는 생성 버튼이 활성화돼 있어도 누르지 않는다.
- 이 간격은 안전을 보장하지 않는다. Flow가 더 엄격한 제한이나 명시적 대기 시간을 표시하면 화면의 제한을 우선하고 더 오래 기다린다.

### 후보 수

- 기본 단위: 먼저 1개 생성, 실패하면 1개 재시도.
- 훅·반전·복잡한 손동작·인체 내부 메커니즘·연속성 핵심 단위: 처음부터 2개.
- 후보는 전체 8초의 인상이 아니라 문장별로 건질 수 있는 1–3초의 행동 수와 정확성으로 고른다.

### 파일럿

일괄 생성 전 두 단위만 만든다.

1. 승인된 무문자 시작 이미지를 I2V 입력으로 사용해 정확히 같은 시작 구도에서 출발하고 첫 2초의 약속을 증명하는 훅 단위.
2. 시리즈의 핵심 시각 문법을 보여주는 메커니즘 또는 반전 단위.

둘 다 통과해야 재질, 팔레트, 렌즈, 조명, 카메라 문법을 잠그고 나머지를 생성한다. 하나라도 실패하면 프롬프트 계약을 고친 뒤 파일럿만 다시 만든다.

프롬프트에 `diorama`가 쓰였다는 사실만으로 합격시키지 않는다. 접점 시트와 원본 재생에서 무광 수지, 조각된 머리카락, 단순 도색 얼굴, 축척 비교물, 미니어처 세트 이음선 가운데 최소 두 가지가 실제로 보여야 한다. 실사 배우·피부·일반 광고 영상처럼 보이면 파일럿 실패다. `conditional_pass`는 전체 생성 진입 조건을 충족하지 못한다.

### 구간 수확

문장마다 `candidate_id`, `source_in`, `source_out`, `speed_ratio`, `optical_flow`, `reject_reason`, `native_audio_decision`, `audio_harvest_window`, `sync_error_frames`를 기록한다. 기본은 정상 속도다. TTS보다 짧고 대체 후보가 없을 때만 속도를 늦추며, 광학 흐름을 켠 뒤 얼굴·손·가슴 압박·전극·의료기구의 형태를 프레임 단위로 검사한다. 네이티브 오디오는 화면 사건과 ±2프레임, 가짜 말소리·음악 없음, 공간 연속성 통과 때만 살린다.

- 생성 실패 단위를 앞선 장면 재사용으로 덮지 않는다. 같은 원본을 여러 문장에 쓸 때는 하나의 연속 행동을 인접 구간으로 나눈 경우에만 허용하며, 의미가 다른 문장이나 엔딩을 채우기 위한 반복은 실패다.
- 최종 매니페스트에는 `unique_source_count`, `reused_source_windows`, `failed_units`, `conditional_pass_units`를 기록한다. 실패 단위가 하나라도 편집 재사용으로 대체됐거나 프리미엄 시각 단위에 `conditional_pass`가 남으면 최종 QA에 진입하지 않는다.

## 11–14 TTS가 소유하는 편집

- 최종 TTS의 문장 경계와 단어 타임코드가 유일한 시간축이다.
- 승인 대본 전체를 한 번에 합성하는 것이 기본이다. 공급자 제한이 있을 때만 큰 이야기 구간 최대 3개로 나누며 문장별·한두 문장별 TTS 파일을 이어 붙이지 않는다.
- 문장 시작 전에 그 문장의 핵심 결과를 보여주지 않는다.
- 문장이 끝나기 전에 다음 문장의 의미 장면으로 넘어가지 않는다.
- 영상 프레임 수는 `round(최종 TTS 초 × fps)`로 계산하고 TTS와의 차이는 최대 1프레임으로 제한한다.
- 자막은 Gmarket Sans Bold 100px, 외곽선 30px, 그림자, 수동 줄바꿈을 사용한다.
- 자막 블록 중심은 1080x1920 기준 `x=540px`, `y=1200px`, 즉 화면 높이의 `10/16=62.5%`에 고정한다.
- 자막 페이지는 최종 TTS 강제정렬의 실제 단어 시작·끝 시각으로 구동한다. 페이지 수로 문장 시간을 균등 분할하거나 추정 타이밍을 쓰면 실패다.
- 모든 화살표·선·줌·스티커·효과음은 실제 발화 문구, 실제 화면 앵커, 인과 목적을 가져야 한다.
- 편집기에서 모든 문장 컷에 동일한 입장용 위아래 이동·확대·불투명도 리셋을 일괄 적용하지 않는다. 소스 카메라의 출구 속도와 다음 소스의 입구 속도가 이어지도록 컷별로 설계한다.
- 피사체 강조 오버레이는 같은 카메라 컨테이너 또는 프레임별 추적 좌표를 사용한다. 고정 화면 좌표로 움직이는 병·손·기계·얼굴을 가리키는 구현은 실패다.
- 자동 자막 결과는 초안일 뿐이다. 한글, 숫자, 영문, 의학 용어를 사람이 보이는 형태로 다시 검수한다.
- 최종 영상의 `t=0.000초` 프레임은 승인 썸네일과 시각적으로 일치해야 한다. 첫 2초에 검은 화면·로고·별도 타이틀·무관한 점프컷이 있으면 불합격이다.
- `sentence_alignment`는 최종 단어 강제정렬에서 문장별 소유 구간을 만든 유일한 원본이다. 같은 `sentence_id`의 `scene_windows` 시작·끝은 해당 문장 구간과 최대 1프레임만 차이 날 수 있다.
- 각 자막 페이지는 `token_start_index`와 `token_end_index`를 가진다. 모든 단어 토큰을 원래 순서대로 정확히 한 번 소유하고, 페이지 시작·끝은 소유한 첫·마지막 단어와 최대 1프레임만 차이 나야 한다.
- 최종 렌더 전과 렌더 후에 `scripts/validate_tts_caption_contract.py <episode-contract.json>`을 실행한다. 둘 중 한 번이라도 실패하면 업로드를 차단한다.

### 필수 동기화 보정 루프

1. 최종 TTS와 강제정렬을 잠근 뒤 `sentence_alignment`, `scene_windows`, `caption_pages`를 새로 계산한다. 이전 임시 TTS의 타임라인은 재사용하지 않는다.
2. 장면이 짧으면 같은 Flow 원본의 다른 좋은 구간 수확, 정상적인 서브클립 경계 조정, 작은 속도 보정 순서로 맞춘다. 얼굴·손·의료기구 변형이 생기면 광학 흐름을 쓰지 않고 후보를 다시 수확하거나 재생성한다.
3. 장면이 길면 의미 행동을 보존한 채 끝부분을 자른다. 다음 문장 장면을 앞당기거나 검은 화면·정지 프레임·무관한 B-roll로 빈 시간을 메우지 않는다.
4. 자막이 어긋나면 개별 자막을 눈대중으로 이동하지 않는다. 최종 단어 강제정렬에서 페이지와 줄바꿈을 다시 만든다.
5. 새 RC를 렌더하고 전체 길이, 모든 문장 경계, 모든 자막 페이지, 첫말·끝말, 조기 장면 전환을 다시 검사한다. 실패가 남으면 2–5를 반복한다.
6. `sync_review.status=PASS`, `premature_scene_cut_count=0`, `missing_caption_token_count=0`, `overlapping_caption_page_count=0`, 장면·자막 최대 오차가 각각 1프레임 이하일 때만 `final-sync.lock.json`을 만든다.
7. 잠금에는 최종 MP4, TTS, 강제정렬, 자막 매니페스트, 승인 썸네일, 첫 프레임 캡처의 SHA-256을 보존한다. 이후 파일 해시가 하나라도 바뀌면 잠금을 무효화하고 다시 검수한다.
8. 모든 컷의 전후 12프레임 스트립과 0.25배속 경계 영상을 검사한다. 카메라 위치 점프, 축 반전, 확대 초기화, 수직 바운스, 추적 오버레이 미끄러짐은 각각 0건이어야 한다.
9. QA는 JSON에 앵커 필드가 존재하는지만 세지 않는다. 실제 렌더의 시작·중간·끝 프레임에서 대상과 오버레이의 거리를 측정하고, 무음 재생으로 디오라마 정체성과 운동 연속성을 사람이 보이는 형태로 확인한다.

## 잠금 규칙

각 단계의 잠금은 최소 다음을 가진다.

```json
{
  "stage_id": "08_pilot_generation",
  "status": "completed",
  "input_hashes": {},
  "output_hashes": {},
  "approved_by": "user_or_validator",
  "completed_at": "ISO-8601",
  "lock_sha256": "64-hex"
}
```

완료 단계의 입력 해시가 달라지면 그 단계와 뒤 단계 잠금을 모두 무효화한다. `blocked`는 실패가 아니라 다음 비용 지출과 잘못된 게시를 막은 정상 상태다.
