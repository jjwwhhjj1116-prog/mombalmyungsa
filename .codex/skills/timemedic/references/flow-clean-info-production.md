# 몸의 발명사 Google Flow CLEAN→TARGET 제작 규칙

## 출처와 적용 범위

공개 참고 영상 `공학 쇼츠는 이렇게 만들 수 있습니다 (ft. 구글 플로우, 코덱스)`와 제작자가 배포한 `CODEX_ENGINEERING_SHORTS_WORKFLOW_KR.md`에서 확인한 핵심 구조를 몸의 발명사에 맞게 재설계한다.

- 영상: https://www.youtube.com/watch?v=xRed28mz4-s
- 공개 MD: https://drive.google.com/file/d/1YsCMvOxbz9bTHXLWU1kN-oXGavl4Do9b/view?usp=sharing

이 자료는 유사한 공학 설명 영상의 공개 워크플로를 보여준다. 특정 타 채널이 실제로 동일한 방식으로 제작했다는 증거로 단정하지 않는다. 화면 스타일을 복제하지 않고 상태 쌍, ID, 승인 게이트, 공간 그래픽 조립 원리만 사용한다.

## 핵심 계약

```text
승인 대본
→ 최종 TTS와 단어 정렬
→ 문장별 장면 ID
→ CLEAN 시작 상태
→ 같은 구도의 TARGET 상태
→ Flow 생성 클립
→ 정확한 텍스트·수치와 의미 오버레이
→ TTS 기준 트림·편집·QA
```

문장 하나가 클립 하나를 소유한다. 장면은 해당 문장의 TTS가 끝나기 전에 바뀌지 않는다. 영상 길이를 먼저 정해 대본을 끼워 맞추지 않고 최종 TTS가 장면 경계를 결정한다.

## 세 가지 Flow 모드

### `narrative_action`

역사 인물의 행동, 현재의 익숙한 의료 행동, 딜레마, 제작·조립처럼 동사가 주인공인 장면이다.

- 시작: `CLEAN_START`
- 목표: 같은 인물·세트·렌즈의 `CLEAN_END`
- 피사체는 문장의 동사를 시작→중간→완료한다.
- 카메라는 두 앵커 사이를 이동하고 환경은 동작에 반응한다.
- 생성 텍스트와 INFO 그래픽은 넣지 않는다.

### `spatial_explainer`

압력, 감염 경로, 혈류, 하중, 절개, 치수, 전후 비교처럼 원리를 공간에서 설명하는 장면이다.

- 시작: 그래픽과 글자가 없는 `CLEAN`
- 목표: 같은 구도에 선·화살표·입자·절개면·빈 라벨 플레이트만 추가한 `INFO_GEOMETRY`
- CLEAN과 목표의 카메라, 크롭, 인물, 재료, 조명, 물리 상태를 보존한다.
- 그래픽은 실제 3D 공간의 표면과 앵커에 붙고 원근·시차·가림을 따른다.
- 정확한 한글·영문·숫자·단위는 Flow가 만들지 않는다. Remotion의 결정적 텍스트 레이어가 최종 합성한다.

### `verified_evidence`

공식 문서, 실제 사진, 논문 표, 연도·숫자 증거를 보여주는 장면이다.

- 검증된 원본을 우선한다.
- 생성 모델이 문서나 숫자를 다시 그리지 않게 한다.
- 카메라 이동, 종이 슬라이드, 하이라이트, 카운터는 프로그램식 편집으로 만든다.

## 장면 ID와 파일 대응

```text
S01                  문장 장면
KF-S01-CLEAN         시작 상태
KF-S01-TARGET        행동 완료 또는 INFO_GEOMETRY 상태
CLIP-S01             Flow 원본 MP4
OVERLAY-S01          정확한 텍스트·수치·선의 편집 매니페스트
FINAL-S01            TTS에 맞춘 최종 장면
```

대본, TTS, CLEAN, TARGET, CLIP, OVERLAY가 같은 `sentence_id`로 1:1 대응해야 한다. 파일명 오름차순은 대본 순서와 같아야 한다.

## 승인 게이트

1. 사실과 대본을 두 번 검수하고 승인한다.
2. 최종 TTS와 단어 정렬을 잠근다.
3. 문장별 장면표·ID·`flow_mode`를 승인한다.
4. CLEAN을 중간 품질 이상으로 생성하고 전수 검수한다.
5. TARGET을 CLEAN 편집 패스로 만들고 동일 구도 여부를 검수한다.
6. 오프닝과 핵심 반전에서 샘플 2클립만 먼저 생성한다.
7. 두 샘플이 무음 동사·형상 안정성·공간 그래픽·TTS 길이를 모두 통과한 뒤에만 배치 생성한다.
8. 각 MP4를 대표 프레임과 실제 재생으로 검수한다.
9. 정확한 텍스트·수치·자막·SFX를 편집에서 합성한다.
10. 최종 QA 뒤 게시 승인을 받는다.

유료 생성 전에 `human_approved=true`와 해당 단계 승인 잠금이 모두 있어야 한다.

## 생성 클립 시간 구조

문장 오디오보다 긴 4·6·8초 중 가장 짧은 길이를 선택하고 앞뒤 편집 핸들을 확보한다.

`narrative_action`:

- 0–15%: 시작 자세와 공간을 읽힌다.
- 15–75%: 동사를 수행하며 카메라가 목표 앵커로 이동한다.
- 75–100%: 행동을 완료하고 다음 장면이 이어 받을 끝 상태를 남긴다.

`spatial_explainer`:

- 0–12%: CLEAN과 실제 환경 움직임만 보인다.
- 12–28%: 의미 앵커가 켜진다.
- 28–50%: 선·파면·화살표 몸통·절개 경계가 순차 생성된다.
- 50–70%: 빈 라벨 플레이트와 수치 자리의 구조가 조립된다.
- 70–88%: 흐름·압력·하중 펄스가 실제 방향으로 이동한다.
- 88–100%: 목표 구도에 수렴하고 6–10프레임 안정적으로 유지한다.

최종 글자와 숫자는 이 안정 구간에 코드로 얹는다. 문장보다 클립이 짧으면 장면을 미리 넘기지 말고 문장을 의미 단위로 나누거나 더 긴 생성 길이를 선택한다.

## TARGET 제작 규칙

- TARGET은 새 그림이 아니라 CLEAN의 편집본이다.
- 인물 얼굴, 손가락 수, 핵심 사물, 세트 비율, 렌즈와 카메라 높이를 바꾸지 않는다.
- 한 장에는 하나의 인과만 시각화한다.
- 화살표는 시작점·방향·경계·결과를 가진다.
- 선은 실제 대상에서 시작하고 끝난다. 허공에 임의의 원·체크·선이 생기면 실패다.
- 거대한 문장형 타이틀과 설명 자막은 TARGET에 넣지 않는다.
- 의료 위험·손상은 코랄, 정상 흐름은 청록, 증거와 최종 수치는 앰버처럼 에피소드 팔레트를 일관되게 쓴다.

## Flow 프롬프트 필수 필드

```json
{
  "sentence_id": "S01",
  "flow_mode": "spatial_explainer",
  "trigger_phrase": "감염이 손을 따라 옮겨갔습니다",
  "clean_asset": "KF-S01-CLEAN.png",
  "target_asset": "KF-S01-TARGET.png",
  "subject_motion": "감염 입자가 장갑 표면에서 손목 쪽으로 이동한다",
  "camera_motion": "장갑 끝에서 손목 앵커까지 짧게 추적하고 부드럽게 착지한다",
  "environment_motion": "세척수와 미세 방울이 반대 방향으로 흘러 인과를 구분한다",
  "graphic_build": "앵커 점등 뒤 경로선과 화살표가 순서대로 조립된다",
  "continuity_in": "이전 장면의 오른쪽 이동을 이어 받는다",
  "continuity_out": "손목 앵커를 다음 장면 왼쪽 상단에 남긴다",
  "avoid": "텍스트 생성, 임의 선, 허공 체크, 얼굴 변화, 손가락 변형, 구조 모핑",
  "causal_purpose": "접촉 경로가 반복 감염의 원인이었음을 보여준다"
}
```

`trigger_phrase`는 잠긴 내레이션에 실제로 존재해야 한다. `causal_purpose`를 한 문장으로 설명할 수 없으면 그래픽과 카메라 동작을 삭제한다.

## QA 실패 조건

- CLEAN과 TARGET의 구도나 인물·사물이 달라짐
- 문장 종료 전에 다음 장면으로 전환
- 시작과 끝 자세가 거의 같고 사진만 확대됨
- 의미 대상이 아닌 곳에 선·원·체크가 붙음
- 흐름·압력·하중 화살표가 반대 방향임
- 생성된 한글·영문·숫자가 화면에 남음
- 그래픽이 평면 HUD처럼 화면에 붙고 원근·가림을 무시함
- 무음으로 보았을 때 동사 또는 인과를 한 문장으로 설명할 수 없음
- 마지막 목표 상태가 안정되지 않아 읽을 수 없음

실패 장면만 다시 만든다. 통과한 CLEAN·TARGET·MP4를 전체 재생성하지 않는다.
