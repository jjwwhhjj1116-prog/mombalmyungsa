# 의미 결합형 VOX/VOK 모션

## 용어 주의

- `Vox 스타일`은 Vox 계열 설명 영상에서 널리 보이는 편집 문법을 가리키는 고수준 표현이다.
- `복스 엔진`은 gasket_love가 자신의 Claude 코드 워크플로에 붙여 사용한 이름이다. 공개 표준이나 확인된 오픈소스 제품명으로 취급하지 않는다.
- `gasket_love`는 게시자 계정명이지 합성 기법명이 아니다.
- `VOK`의 공식 풀네임을 임의로 만들지 않는다. 타임메딕 내부에서는 이 구현을 `의미 결합형 모션 파이프라인`이라고 부른다.

## 원칙

```text
발화 문구 → TTS 타임코드 → 의미 대상 → 앵커 좌표 → 카메라 경로 → 대상 반응 → 사운드 큐 → 인과 목적
```

문장 옆에 임의의 줌·셰이크·오버레이를 붙이지 않는다. `causal_purpose`가 없으면 삭제한다.

## 비주얼 세계

- 전시 모형이 살아 움직이는 3D 의학 박물관 미니어처 + CAD 과학 설명
- 절개, 투명화, 분해도, 단면, 입자 흐름, 방향선, 숫자 증거, 카메라 관통
- 역사 인물은 같은 3D 세계의 조형 캐릭터 또는 검수된 실제 자료
- VOX 층은 종이 텍스처, 컷아웃, 연필 하이라이트, 손그림 선, 짧은 타이포 타격
- 따뜻한 실사풍 역사 이미지 한 장을 흔드는 방식과 텍스트 카드 교체 방식은 금지

## 의미 매핑

- 신체 부위: 해당 앵커로 매크로 푸시인
- 통증·손상: 해당 앵커에서만 균열·염증·충격 시작
- 놀람·상식 반박: 관련 얼굴·물체에 4–6프레임 스냅 줌 후 홀드
- 반복: 카운터와 손상 상태를 단계적으로 갱신
- 딜레마: 화면 양분, 양쪽 손실을 같은 리듬으로 착지
- 원리: 절개·투명화 후 입자·화살표의 실제 경로를 카메라가 따라감
- 질문 전환: 증상에서 줌아웃 → 시점 축 전환 → 원인 구조로 재진입
- 해결책 제작: 분해도 → 부품 스태거 → 조립 완료
- 예상 밖 확산: 한 사람에서 여러 사용자·현재 표준으로 줌아웃
- 증거: 카메라 이동을 줄이고 기록·숫자를 대상 옆에 고정
- 루프: 현재 장면으로 매치컷

## 카메라

- 넓은 이동은 빠르게 가속하고 목표 앵커에서 부드럽게 감속한다.
- 이동 중 방향성 블러를 넣고 도착 뒤 제거한다.
- 확대율이 높을수록 미세 핸드헬드 진폭을 조금 키운다. 자막·UI는 흔들지 않는다.
- 손그림 선은 끝점이 이동하고 카메라는 끝점을 따라간다.
- 이미지와 그 이미지에 붙는 화살표·원·입자는 같은 카메라 컨테이너에 둔다.
- 목표 앵커가 없으면 줌하지 않는다.

```json
  "trigger_phrase": "피부가 갈라지고",
  "subject_focus": "hampton_hand",
  "anchor_id": "left_palm_crack",
  "camera_move": "macro_push_in",
  "camera_easing": "fast_travel_soft_arrival",
  "overlay": "crack_spread",
  "transition": "zoom_blur",
  "duration_seconds": 2.4,
  "image_prompt": "해당 문장의 시작 프레임을 만드는 9:16 미니어처 키프레임 프롬프트",
  "video_prompt": {
    "subject_motion": "햄프턴이 소독액에서 손을 급히 빼며 통증에 손가락을 움츠린다",
    "camera_motion": "대야에서 왼손바닥 균열까지 빠르게 매크로 푸시인하고 부드럽게 착지한다",
    "environment_motion": "소독액이 흔들리고 작은 방울이 손끝에서 떨어진다",
    "avoid": "정지 포즈, 무의미한 입 모양, 손가락 변형, 얼굴 변화, 텍스트"
  },
  "continuity_in": "이전 장면의 아래 방향 손 움직임을 이어 받는다",
  "continuity_out": "갈라진 손바닥이 다음 장면의 같은 위치와 크기로 남는다",
  "match_anchor": "left_palm_crack",
  "causal_purpose": "반복된 소독이 손상으로 이어졌음을 보여준다",
  "asset_route": "image_to_video"

```

필수 필드가 하나라도 없거나 `trigger_phrase`가 내레이션에 없으면 실패다. TTS word timing 전에는 임의의 절대 타임코드를 만들지 말고 `pending_tts_word_alignment`로 둔다.

## 1문장 1클립과 연결

- 문장 하나에 한 화면 동사만 둔다. 두 행동·두 시간·두 결론이 있으면 문장을 나눈다.
- 모든 스토리보드 장면은 `대사(dialogue)`, `장면(scene)`, `감정(emotion)`을 같은 행에 명시한다. 셋 중 하나라도 비어 있으면 이미지·TTS·영상 생성으로 넘기지 않는다.
- `장면`은 화면에 보이는 시작 행동, 완료 행동, 카메라가 도착할 의미 앵커를 포함한다. 추상적인 “설명한다”, “강조한다”만으로 쓰지 않는다.
- `감정`은 음성 태도만 뜻하지 않는다. 인물의 표정·몸짓, 카메라 가속·홀드, 환경 반응이 같은 감정 방향을 공유해야 한다.
- 문장마다 독립된 `image_prompt`와 `video_prompt`를 만든다.
- 이미지는 시작 키프레임으로만 쓰고 최종 타임라인에는 움직이는 MP4를 배치한다.
- 매 클립에서 피사체·카메라·환경 중 최소 두 요소를 움직인다. 호흡·램프 깜빡임·느린 줌만으로는 통과하지 않는다.
- 연속 동작 판정 게이트: 첫 프레임의 자세·위치와 마지막 프레임의 자세·위치가 분명히 달라야 한다. 주인공은 문장의 동사를 시작→중간→완료로 수행하고, 카메라는 두 개의 명시된 앵커 사이를 실제로 이동하며, 세트 장치나 전경 레이어도 같은 시간에 반응한다.
- 인물이 서 있거나 바라보기만 하고 카메라가 사진을 확대하는 클립, 시작과 끝 구도가 거의 같은 클립, `slow zoom`·호흡·눈 깜빡임·조명 변화만 있는 클립은 생성 성공 여부와 관계없이 폐기한다.
- 최종 검수는 음소거 상태에서 한다. 내레이션 없이 보아도 누가 무엇을 시작했고 어떻게 끝냈는지 동사 하나로 말할 수 없으면 실패다.
- 앞 장면의 `continuity_out`과 다음 장면의 `continuity_in`은 같은 물체·방향·구도 중 하나를 공유한다.
- 기본 연결은 행동 매치, 물체 매치, 카메라 운동 연속, 벽 통과, 휩팬, 포커스 풀이다.
- 문자 오버레이는 치수·수치·인물명·재질명·결정적 키워드에만 쓴다. 내레이션 전체를 화면에 다시 쓰지 않는다.

### 연속 운동 운반체

- 각 문장은 `motion_carrier` 하나를 가진다. 예: 오른손의 이동, 병뚜껑의 회전, 기포의 상승, 레일 위 동전, 카메라의 좌→우 이동.
- 다음 문장은 이전 `motion_carrier`를 그대로 이어받거나, 화면에서 보이는 접점에서 새 운반체로 넘긴다. 예: 회전하는 뚜껑 → 원형 게이지 바늘, 상승 기포 → 위로 올라가는 연도 카드.
- 컷 경계마다 `transition_mechanism`, `entry_velocity`, `exit_velocity`, `shared_screen_zone`을 기록한다. 두 항목 이상 불일치하면 새 클립을 수확하거나 연결 프롬프트를 다시 만든다.
- 반전 직전의 홀드 외에는 0.7초가 넘는 죽은 정지를 허용하지 않는다. 다만 끊임없는 흔들림·입자 남발도 실패이며, 항상 하나의 의미 대상만 운동을 주도한다.
- 최종 무음 검수에서 컷을 넘겨도 시선이 같은 대상이나 방향을 자연스럽게 따라갈 수 있어야 한다. 매 컷이 새 포스터처럼 다시 시작하면 실패다.

### 컷 경계 안티 셰이크 계약

- 생성 원본에 카메라 운동이 있으면 편집기는 그 운동을 보존한다. 문장마다 `translateY`, `scale`, 회전, 팬 방향을 초기화해 가짜 입장 모션을 다시 거는 구현은 금지한다.
- 홀수·짝수 문장만을 이유로 카메라 방향을 번갈아 바꾸지 않는다. 방향 반전은 화면에서 보이는 물체 충돌, 인물의 시선 전환, 휩팬 반환처럼 의미상 원인이 있을 때만 허용한다.
- 동일 원본의 연속 구간을 여러 문장에 나눠 쓸 때 원본 시간과 카메라 위치는 연속되어야 한다. 각 서브클립을 새 영상처럼 확대·위치 초기화하면 실패다.
- 최종 QA는 모든 컷의 앞뒤 12프레임 스트립과 0.25배속 경계 영상을 만든다. 위치 점프, 축 반전, 확대 초기화, 수직 바운스가 하나라도 보이면 해당 경계를 다시 편집하거나 재생성한다.
- 피사체에 붙는 원·화살표·라벨·입자는 피사체와 같은 카메라 변환 컨테이너에 두거나 프레임별 추적 좌표를 사용한다. 화면 고정 좌표는 출처·채널명 같은 HUD에만 허용한다.
- 추적형 오버레이는 등장 구간의 시작·중간·끝 세 프레임에서 목표와의 거리 오차를 검사한다. 목표에서 미끄러지거나 엉뚱한 빈 공간을 가리키면 실패다.

## 고정 타이포 계약

- 주요 내레이션·후킹·결정적 키워드는 `Gmarket Sans Bold`만 사용한다.
- 영상 본문 자막은 1080x1920 기준 `100px`, 외곽선은 검정 `30px`, 그림자 효과를 사용한다. 썸네일은 별도 참고 구도의 `220–340px` 대형 Gmarket Sans Bold를 사용한다.
- 자막 블록의 중심 앵커는 `x=540px`, `y=1200px`, 정규화 좌표 `(0.5, 0.625)`로 고정한다. 화면 상단을 1, 하단을 16으로 나눴을 때 10의 위치다.
- 외곽선은 `paint-order: stroke fill`로 채움 뒤에 그려 글자 내부가 잠식되지 않게 한다.
- 긴 문장을 100px 아래로 축소해 우겨 넣지 않는다. 최종 TTS 단어 타임코드에 맞춰 2–4어절 자막 페이지로 나누고, 조사·어미가 부자연스럽게 갈라지지 않게 수동 줄바꿈한다.
- 자막 페이지의 시작·끝은 강제정렬된 단어의 실제 시각에서 가져온다. 문장 시간을 페이지 수로 균등 분할하는 구현은 금지한다.
- 워터마크·작은 증거 라벨은 크기 예외가 될 수 있으나 글꼴은 동일하게 유지한다.

## 밀도

- 16비트는 이야기 구조이고 최종 내레이션은 24–36개 짧은 문장으로 확장한다.
- 문장 수와 영상 클립 수를 같게 유지한다.
- 클립은 평균 1.7–3.2초로 자르고, 4–6초 생성본은 TTS에 맞춰 트림·속도 조절한다.
- 절개·투명화·패럴랙스·타이포·도해는 움직이는 클립 위의 설명층으로 사용한다.
