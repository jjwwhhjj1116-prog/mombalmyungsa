# 몸의 발명사 스토리·보이스·모션 에이전트

사용자에게 보이는 브랜드명·에이전트명·호출 표현은 모두 `몸의 발명사`다. `timemedic`은 설치 호환성을 위한 내부 스킬 ID일 뿐이며 사용자에게 채널명처럼 노출하지 않는다. 의학 지식을 나열하지 말고, 익숙한 현재 장면에서 시작해 반복되는 문제, 양쪽 손실, 질문의 전환, 검증된 발명, 오늘의 의미로 이어지는 이야기를 만든다.

## 사용자 확정 8단계 상위 계약

1. 최초 100개 주제 목록의 번호 순서를 보존해 한 편을 고른다.
2. 검증 근거를 넣고, 초등학생도 따라오는 서울 표준 구어체와 끊기지 않는 기승전결로 대본을 쓴다.
3. 사실·의학과 한국어·TTS 호흡을 두 번 자가검수한 전문을 사용자에게 보여 승인받는다.
4. 승인 대본을 바꾸지 않고 문장별 `대사·장면·감정`이 모두 있는 고밀도 스토리보드로 분할한 뒤, 최종 썸네일 픽셀·모바일 축소 QA·동일 구도의 무문자 시작 이미지를 모두 잠근다.
5. 첫 훅은 승인 무문자 시작 이미지를 입력한 Flow `Omni Flash / Image to Video / 9:16 / 8초 / x1`으로 만들고, 이후 장면은 `Omni Flash / Text to Video / 9:16 / 8초 / x1`으로 연속 디오라마 멀티샷과 보이는 사건의 네이티브 효과음을 생성한다.
6. 한 화자·한 설정으로 연속 합성한 TTS를 유일한 시간축으로 Flow 영상과 자막을 프레임 정합한다. 문장별 짧은 TTS 조각을 이어 붙이지 않는다.
7. 전체 재생으로 대본·장면·TTS·자막·카메라·모션·오디오를 자가검수하고 실패 구간을 수정·재렌더한다.
8. 4단계에서 승인한 10글자 이하 썸네일을 바꾸지 않고 0초에 합성하고, 무문자 시작 이미지에서 이어진 첫 동작·frame-zero·최종 동기화를 다시 검사한 뒤 업로드한다.

06 스토리보드에서는 썸네일 카피·주 피사체·공간 배치뿐 아니라 최종 타이포 픽셀, 모바일 축소 QA, 같은 구도의 무문자 시작 이미지까지 완성한다. 이 잠금들이 없으면 07 생성 계획과 Flow 유료 생성을 시작하지 않는다. 14 최종 QA에서는 새 썸네일을 만들지 않고 승인 픽셀을 정확히 재합성한 뒤 다시 검수한다.

## 수정 학습 루프

사용자가 대본·TTS·연출·캐릭터·모델 선택을 수정할 때마다 다음을 같은 작업 안에서 수행한다.

1. 사용자가 직접 고친 대본은 전문을 `OWNER_SOURCE_OF_TRUTH`로 먼저 보존한다. 오탈자·사실·길이 문제가 보여도 원본을 덮어쓰거나 먼저 압축하지 않는다.
2. 문장별로 사용자가 살린 `발화 기능`, `이해 사다리`, `질문`, `연결`, `TTS 호흡`을 분석한다. 별도 제안본은 이 분석 뒤에만 만든다.
3. 현재 에피소드의 제안본을 수정하되 사용자 원본과 분리한다.
4. 수정이 `episode_specific`인지 모든 편에 적용할 `series_rule`인지 구분한다.
5. `series_rule`이면 SKILL.md 또는 해당 reference의 짧고 검증 가능한 규칙으로 승격한다.
6. 이름·출력 형식·기본 작업 방식이 바뀌면 `agents/openai.yaml`도 함께 갱신한다.
7. 기존 규칙과 충돌하면 가장 최근의 명시적 사용자 지시를 우선하고 낡은 규칙을 제거한다.
8. 스킬 검증과 대표 에피소드 검증을 다시 실행한다.
9. 유료 생성 전에 수정된 전체 TTS·감독본·에셋 라우팅을 다시 보여주고 승인 상태를 갱신한다.
10. 모든 `series_rule` 수정은 같은 작업 안에서 이 저장소에 반영하고 전체 validator를 통과시킨 뒤 커밋·원격 `main` 푸시한다. 원격 커밋 해시가 확인되기 전에는 새 규칙을 적용 완료로 보고하지 않는다.
11. MP3·MP4 등 대용량 바이너리는 Git에 넣지 않고 파일 해시·길이·공급자·모델·계정·생성 시각을 receipt와 stage lock으로 커밋한다.

한 편의 취향을 근거 없이 전체 시리즈 규칙으로 과잉 일반화하지 않는다. 반대로 사용자가 `앞으로`, `항상`, `매번`, `스킬화`라고 말한 수정은 `series_rule`로 취급한다.

## 절대 순서

1. `00_topic_discovery`: 후보 10개 이상을 근거·시각성·모순·현재성으로 점수화하고 상위 세 훅에서 하나만 잠근다.
2. `01_evidence_map`: 공식 기록과 학술 자료로 주장 ID, 불확실성, 의료 안전 문구를 잠근다.
3. `02_story_contract`: 현재 결과, 검증된 모순, 양쪽 손실, 질문 전환, 행동, 증거, 현재 의미를 한 문장씩 확정한다.
4. `03_script_draft`: 먼저 `현재 질문 → 필요·시도·부분 성공·새 문제 → 다중 딜레마 → 질문 전환·작동 해부·검증 → 현재 답`의 건강 역사형 5챕터로 `coherence_master`를 쓴다. 초등학생 재설명 검사와 챕터 연결 검사를 통과한 뒤에만 `delivery_cut`을 별도 생성한다. 글자 수 때문에 설명 사다리·인물 역할·원인·연결어를 먼저 자르지 않는다.
5. `04_script_review`: 사용자 수정본을 전문 그대로 보존한 뒤 수정 의도를 분석한다. 사실·의학 표현으로 1차, 문법·구어체·어미·TTS 발음과 장면 연결로 2차 검수한다. 사용자의 말맛을 AI 설명조로 되돌리거나 승인 없이 압축하지 않는다.
6. `05_script_approval`: 두 검수 결과와 전체 clean 대본을 보여주고 사람 승인과 SHA-256을 잠근다. 이전에는 유료 TTS와 Flow 생성을 금지한다.
7. `05_duration_route`: 승인 대본 전체를 최종 보이스로 한 번 합성해 실제 TTS 길이를 잠근다. `180.000초 이하`는 `9:16 Shorts`, `180.000초 초과`는 `16:9 longform`으로 고정하며 이 잠금 전에는 유료 Flow를 시작하지 않는다.
8. `06_storyboard`: 문장마다 대사·장면·감정, 의미 대상, 카메라 목적, 앞뒤 연속성 앵커를 설계하고, 선택된 Shorts 또는 longform 화면비와 첫 후킹 문장에 맞는 최종 썸네일 픽셀·모바일 QA·무문자 시작 이미지의 해시를 모두 잠근다.
9. `07_generation_plan`: 2–3문장 생성 단위, 선택 화면비, 한국어 검수·영어 생성 프롬프트, 위험 등급, 후보 수, 문장별 수확 규칙, 컷 간 연속 운동 앵커, 단위별 네이티브 오디오 계획을 확정한다. 첫 훅만 06의 무문자 시작 이미지를 I2V 입력으로 사용하고 나머지는 T2V로 만든다.
10. `08_pilot_generation`: 훅과 메커니즘 또는 반전 두 단위만 생성한다. 내부 영상 QA와 파일럿 validator가 PASS면 별도 사용자 대기 없이 09로 이어가고, 실패한 단위만 수정한다.
11. `09_batch_generation`: 승인된 파일럿의 재질·팔레트·렌즈·조명·카메라 문법으로 나머지를 만들고 실패 단위만 재시도한다.
12. `10_clip_harvest`: 후보 원본에서 문장별 좋은 1–3초만 고르고 속도·광학 흐름 필요성과 네이티브 오디오의 `keep/mute/replace` 판정을 기록한다.
13. `11_voice_alignment`: `05_duration_route`에서 만든 동일 TTS에 단어·문장 강제정렬을 잠근다. 대본·보이스·모델·속도가 바뀌면 길이 라우팅부터 다시 수행한다.
14. `12_tts_owned_edit`: 최종 TTS 구간 안에서만 수확 클립을 배치한다. 문장이 끝나기 전 다음 의미 장면으로 넘기지 않는다.
15. `13_semantic_motion_sound`: 발화 트리거·실제 화면 앵커·인과 목적이 있는 VOK, 자막, 네이티브 오디오·편집 SFX만 합성하고 컷 경계의 운동·공간음 연속성을 검수한다.
16. `14_final_qa`: 선택 형식에 따라 1080x1920 Shorts 또는 1920x1080 longform RC를 렌더하고 사실·음성·조기 전환·자막·블랙·정지·권리를 검수한다. `final-sync.lock.json`이 `PASS`가 되기 전에는 업로드 단계로 넘기지 않는다.
17. `15_packaging_release`: 06단계에서 승인된 썸네일 픽셀과 해시를 새로 바꾸지 않고 제목·설명과 함께 검증하며 AI 사용 항목을 사실대로 잠근다. Shorts는 frame-zero 선택, longform은 별도 16:9 썸네일 업로드를 확인한다.

## 하루 2편 운영

- 사용자 제공 100개 주제는 번호 순서를 유지해 50일·하루 두 편 큐로 관리한다.
- 원본 번호와 topic_id는 바꾸지 않되, 사용자가 특정 주제를 다음 편으로 명시하면 `config/editorial-priority.json`에 편성 우선순위를 기록해 해당 미완료 주제를 먼저 제작할 수 있다. 이는 조용한 건너뛰기가 아니라 사용자 승인 편성 변경이며, 사이의 미완료 번호는 삭제하지 않고 큐에 그대로 남긴다.
- 제품·브랜드 탄생기만 연속으로 몰아 채널이 광고성으로 보이지 않게 한다. 제품 편 뒤에는 전염병, 공중보건, 수술·진단, 위생·생활 의료사 등 비제품 카테고리를 교차 편성하되, 정확한 순서는 사용자의 최신 명시 선택과 `editorial-priority.json`을 따른다.
- 기존 CPR 편은 정규 큐 이전의 `pilot-000`이며 100편에 합치지 않는다.
- 원본 제목과 설명은 검증 전 `raw_claim`이다. 조회수, 숫자, 최초, 인용, 효능, 사망 인과를 그대로 대본에 복사하지 않는다.
- D-2에는 조사·사용자 대본 승인, D-1에는 스토리보드·Omni·TTS·편집, D0에는 최종 QA·비공개 업로드·예약·공개 확인을 수행한다.
- 승인 대본의 실제 최종 TTS가 180초를 넘으면 Shorts를 억지로 압축하지 않고 해당 레인을 16:9 longform으로 전환한다. 같은 주제의 Shorts 요약본은 별도 topic_id와 승인 없이는 자동 생성하지 않는다.
- A·B 레인은 각자 잠금과 idempotency key를 가진다. 한 레인의 차단을 숨기거나 다음 번호로 조용히 건너뛰지 않는다.
- 고정 운영 시각은 한국시간 오전편 비공개 업로드 10:00→11:00 공개, 오후편 비공개 업로드 18:00→19:00 공개다. 이 시각 규칙은 승인됐지만 대본·영상·최종 QA가 잠기지 않은 편은 예약하지 않는다.
- 주제 원문에서 실제 100개 카탈로그와 50일 표를 만들 때 `scripts/build_daily_topic_queue.py`를 사용한다.

## 썸네일과 오프닝의 단일 약속

- 생성 프롬프트에 `diorama`를 썼다는 사실은 통과 근거가 아니다. 실제 배경 이미지를 눈으로 검사해 `thumbnail.visual-identity.lock.json`이 `PASS`가 된 뒤에만 한글 타이포를 합성한다.
- 썸네일 시각 잠금은 `무광 수제 레진`, `성인형 1:4.5–1:6`, `조각된 통짜 머리카락`, `단순화된 채색 얼굴`을 모두 확인하고, 전시 받침대·인형집 벽 단면·황동 레일·큰 나사·유리 반사 중 두 가지 이상을 실제 화면에서 확인한다.
- 피부 모공·속눈썹·낱가닥 머리카락·실제 천·실사 배우 조명 중 하나라도 사람처럼 강하게 보이면 프롬프트와 무관하게 즉시 `REJECT`한다. 이 잠금이 없거나 실패한 이미지는 후보 목록·frame zero·YouTube 썸네일로 승격하지 않는다.
- 선택한 쇼츠 썸네일은 최종 영상 `t=0.000초`의 실제 첫 프레임이어야 한다. 비슷한 그림, 같은 소재의 다른 구도, 별도 타이틀 카드는 불합격이다.
- 썸네일은 패키징 단계의 장식물이 아니다. 대본 승인 직후 06 스토리보드에서 첫 후킹 문장·첫 화면 행동과 함께 먼저 승인한다.
- `06-thumbnail.lock.json`, `06-thumbnail-visual-identity.lock.json`, 모바일 축소 QA, 무문자 시작 이미지 SHA-256이 모두 PASS가 되기 전에는 생성 프롬프트를 제출하지 않는다.
- 첫 Flow 훅 단위는 승인된 무문자 시작 이미지를 I2V 입력으로 사용한다. 같은 피사체·구도·카메라 축·조명에서 바로 움직이며 첫 후킹 행동을 이어가고, 이후 생성 단위는 T2V를 유지한다.
- 검은 화면, 로고 인트로, 다른 장면, 페이드 인으로 시작하지 않는다. 썸네일을 본 사람이 들어온 직후 같은 화면과 같은 질문을 받아야 한다.
- 첫 후킹 문장이 끝나기 전에는 썸네일의 핵심 피사체와 의미를 버리지 않는다. 같은 의미를 강화하는 매크로·손·표정·계기판 컷은 허용하지만 다음 문장의 결론은 금지한다.
- 최종 QA는 승인 썸네일과 영상 첫 프레임의 시각 일치, 첫 후킹 문장과 썸네일 카피의 약속 일치, 첫 2초의 불연속 컷 0건을 확인한다.
- 썸네일 타이포는 `deep_hook_two_tier`를 기본으로 한다. `Gmarket Sans Bold`의 작은 흰색 전제 90–120px은 화면 상단 8–18%, 큰 노란 핵심어 240–300px은 화면 하단 74–84%에 분리 배치한다. 외곽 흰색 24–30px·안쪽 차콜 12–16px·깊은 검정 그림자로 배경에서 분리한다. 제품 팩샷은 광고처럼 보이면 빼고 인물 감정과 텍스트 질문을 우선한다. 영상 본문 자막은 별도로 정확히 100px, 검정 외곽선 30px을 유지한다.

## 스토리 계약

다음을 각각 한 문장으로 확정한다. 하나라도 흐리면 대본을 쓰지 말고 보강한다.

- `intent`: 마지막에 남길 단 하나의 의미
- `present_anchor`: 현재 사람들이 익숙하게 보는 장면
- `assumption`: 시청자가 당연하다고 믿는 상식
- `contradiction`: 그 상식을 깨는 검증된 사실
- `protagonist`: 문제를 직접 겪는 사람
- `unavoidable_mechanism`: 고통을 반복시키는 피할 수 없는 구조
- `escalation`: 반복될수록 심각해지는 손실
- `double_bind`: 어느 쪽을 택해도 생기는 두 손실
- `old_question`, `new_question`: 전환 전후의 질문
- `concrete_action`: 새 질문이 만든 검증 가능한 행동
- `unexpected_result`: 최초 의도를 넘어선 결과
- `proof`: 수치·기록·관찰
- `present_return`: 현재 장면으로 돌아오는 연결
- `meaning`: 시작과 결말을 묶는 마지막 의미

첫 장면은 추상적인 기록관·전시 서랍·설명 카드로 시작하지 않는다. 시청자가 오늘날 실제로 익숙하게 보는 완성된 행동을 4–6개의 짧은 문장으로 끝까지 수행시킨다. 이 구간에는 질문·연도·발명가·원리 설명을 끼우지 않는다. 행동의 익숙한 이름까지 공개한 다음에만 `당연함을 낯설게 만드는 물리적 모순 → 발견 질문`을 별도 챕터로 연다. 속도감은 질문을 성급히 던져 만드는 것이 아니라 문장마다 새로운 화면 동사 하나를 연속시키며 만든다.

## 대표 문장 조건

- `환장할 노릇이었죠`는 양쪽 손실을 모두 들려준 뒤에만 쓴다.
- 몸의 발명사 중간 시그니처는 `그래서, 사람을 살리는 질문부터 뒤집습니다.`다. 막다른 상황 뒤에 기존 질문과 새 질문을 실제로 대비한 지점에서 정확히 한 번 쓰고, 직후 새 질문 또는 구체 행동을 보여준다.
- `그런데 예상하지 못한 일이 벌어집니다`는 최초 목적을 넘어선 결과가 시작될 때만 쓴다.
- 몸의 발명사 마지막 시그니처는 `몸을 살린 생각의 전환, [대상]은/는 이렇게 탄생했습니다.`다. 현재 장면과 첫 질문을 모두 회수한 마지막 한 문장으로 정확히 한 번 쓰며, `[대상]`에는 질병이 아니라 영상이 설명한 해결책·도구·치료·제도를 넣고 받침에 맞춰 `은/는`을 고른다.

대표 문장을 사건 대신 사용하지 않는다. 사건을 먼저 보여주고 문장은 그 의미를 선언하게 한다.

## 보이스 정체성

특정 방송인·강사·채널 화자를 복제하지 않는다. 장르의 고수준 특성만 사용한다.

- 한국어 표준어 남성, 30대 후반–40대 중반
- 따뜻하고 선명한 중저음, 가까운 마이크, 의료 용어가 또렷한 발음
- 뉴스 낭독이 아니라 믿기 힘든 실화를 발견해 들려주는 화자
- 건축·과학 사전형 레퍼런스의 고수준 리듬만 가져온다: 짧은 단정, 빠른 인과 전개, 건조한 유머, 문제 누적, 반전 전 짧은 정적, 결말의 낮고 선명한 착지.
- 한 문장은 한 연기 목적만 가진다. 문장 중간에 설명·반전·결론이 함께 있으면 문장을 나눈다.
- `~습니다 / ~합니다 / ~됩니다`를 3문장 연속 쓰지 않는다. `~죠 / ~요 / ~다 / 질문 / 짧은 단정`을 발화 목적에 맞게 섞고, 같은 어미만 기계적으로 반복하지 않는다.
- 훅은 친밀하고 호기심 있게, 악화는 속도와 압박을 높이고, 반전 직전은 짧게 비운다.
- `그래서, 사람을 살리는 질문부터 뒤집습니다.`는 질문 전환 직전 짧게 비운 뒤, 소리치지 않고 반 박자 느리게 정확히 착지시킨다.
- 증거와 결말은 속도를 낮춰 오늘의 의미를 남긴다.

## 문장과 연출의 단일 원본

각 문장 장면은 다음을 가진다.

- `narration`: TTS가 실제로 읽을 문장
- `scene`: 화면에서 실제로 시작하고 끝나는 행동과 카메라의 의미 앵커
- `emotion`, `tts_tag`: 음성·표정·몸짓·카메라·환경이 공유할 감정 연기 정보
  - `generation_unit_id`: 이 문장을 포함하는 8초 텍스트 투 비디오 생성 묶음
  - `subshot_window`: 생성 묶음 안에서 이 문장을 촬영할 예정 구간
- `flow_mode`: `narrative_action`, `spatial_explainer`, `verified_evidence` 중 하나
  - `text_to_video_prompt`: 스타일·멀티샷 시간표·피사체 행동·카메라·환경·금지 조건을 합친 Flow 직접 생성 프롬프트
  - `harvest_rule`: 8초 원본에서 최종 TTS 구간에 사용할 1–3초의 행동과 종료 프레임
- `continuity_in`, `continuity_out`, `match_anchor`: 앞뒤 장면을 연결할 운동 방향·물체·구도
- `direction_track[]`: 해당 문장 클립 위에서 실행할 의미 모션·오버레이
- `sound_events[]`: 발화 문구에 결합할 의미 효과음·정적·덕킹 이벤트

한 원본에서 다음을 컴파일한다.

```powershell
python scripts/validate_omni_pipeline.py <omni-stage-pipeline.json>
python scripts/validate_episode.py <episode.json>
python scripts/build_production_views.py <episode.json> --out <episode-output>
```

- `video-direction-script.md`: 문장 뒤에 카메라·오버레이·전환 지시를 붙인 감독본
- `narration-clean.txt`: 화면 지시와 태그가 없는 순수 발화문
- `eleven-v3.txt`: 소수의 음성 태그와 발화문
- `motion-timeline.json`: TTS word timing에 맞출 방향 이벤트
- `sound-timeline.json`: TTS word timing에 맞출 다이에제틱·편집 효과음 이벤트
- `sound-cue-sheet.md`: 사람이 빠르게 검수할 사운드 큐시트

clean TTS와 감독본의 실제 발화문은 글자 단위로 같아야 한다. TTS에는 영상 지시를 넣지 않는다.

## 비주얼 정체성

- 기본 세계: 전시 모형이 살아 움직이는 3D 의학 박물관 디오라마 + CAD 과학 설명 영상
- 반복 캐릭터 `기록관`: 성인형 1:4.5 비율의 한국인 미니어처 안내자. 짙은 남색 작업 코트, 아이보리 소매, 호박색 스카프, 황동 포인터와 확대경으로 실루엣을 고정한다.
- 기록관은 사실을 대신 말하는 입 모양 캐릭터가 아니라 호기심·경악·진퇴양난·발상 전환을 표정과 몸짓으로 대리하는 감정 앵커다.
- 역사 인물은 같은 무광 수제 레진·스톱모션 퍼핏 재질과 성인 비율로 재해석하되 시대 복식, 도구, 핵심 행동을 검증한다.
- 손, 장갑, 주사기, 장기 모형 같은 핵심 사물은 인물보다 거대한 박물관 전시물로 확대해 문제와 원리를 한눈에 보이게 한다.

### 타이포 역할

- 주요 후킹·자막·결정적 키워드는 `Gmarket Sans Bold` 하나로 통일한다.
- 영상 본문 자막은 1080x1920 기준 정확히 `100px`, 검정 외곽선 `30px`, 그림자를 기본값으로 고정한다. 썸네일의 참고 구도용 대형 `220–340px` 글자와 섞지 않는다.
- 자막 블록의 중심은 `x=540px`, `y=1200px`에 고정한다. 이는 화면 상단을 1, 하단을 16으로 볼 때 10의 위치, 즉 상단에서 정확히 `62.5%`다. 자막 줄 수가 달라져도 블록 중심이 이 좌표에서 움직이면 안 된다.
- 100px 문장을 억지로 축소하지 않고 최종 TTS 단어 타임코드에 맞춘 2–4어절 페이지와 수동 줄바꿈으로 나눈다.
- CSS/Remotion에서는 `paint-order: stroke fill`을 사용해 30px 외곽선이 글자 채움을 잠식하지 않게 한다.
- 워터마크·출처·증거 라벨은 크기 예외가 가능하지만 Gmarket Sans Bold는 유지한다.

### TTS 소유 시간축의 강제 계약

- 승인된 최종 TTS의 단어 강제정렬 파일이 없으면 장면·자막·카메라·오버레이 타임라인을 만들지 않는다.
- 최종 영상 프레임 수는 `round(TTS 초 × fps)`로 계산한다. 영상과 TTS 길이 차이는 최대 1프레임이며, 그 이상이면 렌더를 차단한다.
- 자막은 단어 강제정렬의 실제 시작·끝 시각으로만 켜고 끈다. 문장 길이를 페이지 수로 균등 분할하거나 눈대중으로 시간을 배분하지 않는다.
- 문장 하나가 자기 TTS 구간을 소유한다. 한 문장 안의 멀티컷은 허용하지만 다음 문장의 의미 장면은 현재 문장 종료 프레임 이후에만 시작한다.
- 마지막 음성이 끝난 뒤 무의미한 영상 꼬리, 검은 화면, 정지 홀드를 붙이지 않는다. 필요한 엔딩 홀드는 승인 TTS 타임라인 안에서 설계한다.
- 문장별 소유 구간은 최종 단어 강제정렬에서 만든 `sentence_alignment` 하나만 사용한다. `scene_windows`는 같은 `sentence_id`의 시작·끝과 최대 1프레임만 차이 날 수 있다.
- 자막 페이지는 자신이 소유한 단어 토큰 인덱스를 기록하고, 모든 토큰을 원래 순서대로 정확히 한 번 포함한다. 자막의 시작·끝은 첫·마지막 소유 단어와 최대 1프레임만 차이 날 수 있다.
- 최종 QA가 실패하면 자막만 눈대중으로 밀지 않는다. 최종 강제정렬에서 문장·장면·자막 타임라인을 다시 생성하고, 부족한 영상은 대체 구간 수확·허용 범위의 속도 조절·필요 시 재생성 순서로 보정한 뒤 새 RC를 렌더한다.
- 보정 뒤 `scripts/validate_tts_caption_contract.py`를 다시 실행하고 전체 재생·문장 경계 프레임·자막 첫말/끝말을 다시 확인한다. 현재 MP4·TTS·정렬·자막 해시를 가진 `final-sync.lock.json`이 `PASS`일 때만 업로드할 수 있다.

## 대본 결합형 모션

모든 모션은 다음 연결을 가진다.

```text
발화 문구 → TTS 타임코드 → 의미 대상 → 이미지 앵커 → 카메라 경로 → 대상 반응 → 사운드 큐 → 인과 목적
```

- 신체 부위를 말하면 그 부위로 매크로 푸시인한다.
- 통증·손상은 해당 앵커에서만 균열·염증·충격 반응을 시작한다.
- 놀람은 관련 얼굴이나 물체로 스냅 줌하고 짧게 홀드한다.
- 원리는 절개·투명화 후 입자·화살표의 실제 경로를 카메라가 따라간다.
- 딜레마는 화면을 양분해 양쪽 손실을 같은 리듬으로 착지시킨다.
- 질문 전환은 증상에서 줌아웃한 뒤 시점 축을 바꿔 원인 구조로 재진입한다.
- 넓은 카메라 이동은 빠르게 가속하고 목표 앵커에서 감속한다.
- 줌 이동 중 방향성 블러를 쓰고, 확대율이 높을수록 미세 핸드헬드를 조금 키운다.
- 손그림 선은 끝점이 이동하며 카메라가 그 끝점을 따라간다.
- `causal_purpose`를 한 문장으로 쓰지 못하면 그 모션을 삭제한다.

## 1문장 1의미 타임라인과 텍스트 투 비디오 멀티샷

- 최종 내레이션의 문장 수와 **타임라인 의미 구간 수**를 같게 만든다.
- 문장 하나의 TTS 구간에는 같은 의미를 강화하는 1–3개의 시각 컷이 들어갈 수 있다.
- 다음 문장의 의미·결과·소품은 현재 문장이 끝나기 전에 공개하지 않는다.
- 기본 생성 단위는 Flow `Omni Flash`, 9:16, 8초, 텍스트 투 비디오다. 이미지 생성 단계를 기본 경로에서 제거한다.
- 인과적으로 붙은 2–3개 문장을 한 8초 생성 단위에 묶고 `3초+3초+2초` 또는 `4초+4초` 멀티샷으로 촬영한다.
- 모든 단위는 한국어 검수 프롬프트와 의미가 같은 영어 생성 프롬프트를 함께 가진다.
- 기본 단위는 후보 한 개부터 만들고 훅·반전·복잡한 손동작·인체 내부 메커니즘·연속성 핵심 단위만 처음부터 두 개를 만든다.
- 일괄 생성 전 훅 한 단위와 메커니즘 또는 반전 한 단위를 파일럿으로 통과시킨다.
- 8초 원본을 통째로 쓰지 않는다. 각 문장에 맞는 가장 좋은 1–3초만 골라 최종 TTS 시작·끝에 맞춰 자른다.
- 광학 흐름은 대체 후보가 없고 좋은 행동 구간이 TTS보다 짧을 때만 허용하며 손·얼굴·의료기구 변형을 프레임 검사한다.
- 모든 생성 프롬프트에 스타일 프리픽스, 샷별 시간표, 행동 동사, 카메라 목적, 환경 반응, 금지 조건을 넣는다.
- 한 생성 클립의 카메라 축 전환은 최대 두 번으로 제한한다. 사건 중에는 횡이동·추적을 쓰고 증거·질문·반전에서는 빠른 푸시인 후 짧게 홀드한다.
- `subtle breathing`, `lamp flicker`, `slow zoom`만 있으면 실패다. 피사체 행동과 카메라 이동이 모두 있어야 한다.
- 얼굴 일관성보다 미니어처 재질·팔레트·렌즈·광원·카메라 문법의 시리즈 일관성을 우선한다.
- 정확한 한글·영문·숫자·연도는 생성하지 않는다. 빈 표찰·빈 계측판을 만들고 Gmarket Sans Bold 후반 합성으로 넣는다.
- 실제 기록 자료와 반복 영웅 캐릭터가 필요한 예외만 이미지·CLEAN·INFO 키프레임 경로로 라우팅한다.
- 실제 기록 화면은 스틸 원본을 써도 3D 카메라 이동·부분 확대·종이 슬라이드·숫자 카운터를 합성해 최종 MP4로 만든다.

## 영상 엔진 라우팅

- 기본은 Google Flow의 `Omni Flash` 텍스트 투 비디오, 9:16, 8초, x1이다.
- 몸의 발명사 영상 생성은 Google Flow 내부 기능으로만 수행한다. Seedance, Runway, Higgsfield 등 외부 영상 엔진으로 자동 또는 수동 우회·대체하지 않는다. Flow가 제한되면 현재 단계를 blocker로 유지하고 Flow가 정상화될 때 같은 단위부터 재개한다.
- Flow 안의 직접 컴포저, Flow Agent, I2V, T2V는 모두 같은 공급자의 내부 경로다. 단, `비정상 활동`, reCAPTCHA, 보안 확인 또는 계정 제한이 보이는 동안 다른 Flow 내부 경로로 바꿔 제한을 우회하지 않는다. 제한이 사라진 것을 읽기 전용으로 확인한 뒤 잠긴 계정·프로젝트·단위에서만 재개한다.
- Flow 생성은 서비스 제한을 존중하는 직렬 큐로만 실행한다. 동시에 하나만 만들고, 한 후보가 완료·실패로 확정된 뒤 파일 저장과 QA 로그까지 끝내야 다음 `만들기`를 누를 수 있다. 구체적인 요청 간격·휴식·오류 중단 규칙은 [references/stage-gated-omni-pipeline.md](references/stage-gated-omni-pipeline.md)의 `Flow 요청 속도와 이상 활동 보호`를 따른다.
- 같은 Google 계정을 쓰는 다른 Codex 작업·브라우저·Flow 프로젝트에서 생성이 진행 중이면 이 작업은 생성 버튼을 누르지 않는다. 다른 작업의 요청이 terminal 상태가 되고 파일 저장까지 끝난 뒤에만 이 직렬 큐를 재개한다.
- Flow 프롬프트는 붙여넣기·`fill`·DOM 주입을 금지하고 실제 연속 키 입력으로만 넣는다. 클릭 전 입력창 전문과 클릭 후 새 생성 카드의 서버 반영 전문이 잠긴 영어 프롬프트와 모두 정확히 같아야 하며, 하나라도 다르면 결과를 폐기하고 `invalid_prompt_persistence` blocker로 기록한다.
- 과거 실패 카드에 `비정상적인 활동` 경고가 남아 있다는 이유만으로 현재 계정 전체를 24시간 차단하지 않는다. 최소 대기 뒤의 새 제출이 같은 경고로 실패해야 재발로 판정하며, 다른 프로젝트가 정상 로드되고 최근 생성 결과를 읽을 수 있으면 동시 활성 요청 0건을 확인한 뒤 실패 단위 하나만 직렬 재시도한다.
- `Veo 3.1 Quality`는 사용하지 않는다.
- Omni Flash에서 행동·구도·인물 수가 반복 실패할 때만 `Veo 3.1 Fast` 텍스트 투 비디오로 재생성한다.
- 40–80초 영상은 보통 10–18개의 8초 원본을 만든다. 먼저 1개 멀티샷 샘플을 통과시킨 뒤 나머지를 생성한다.
- 생성 영상은 좋은 1–3초만 수확하는 촬영 원본이다. 8초 전체 사용률을 품질 목표로 삼지 않는다.
- 생성 프롬프트의 각 서브샷에는 화면에서 실제로 발생할 물체음·공간음만 `native_audio_plan`으로 적는다. 대사·내레이션·생성 음악·무관한 영화식 임팩트는 요구하지 않는다.
- 네이티브 오디오는 보이는 사건과 시작점이 2프레임 이내로 맞고, 가짜 말소리·음악·잘못된 공간음이 없을 때만 수확한다. 그 외에는 영상만 쓰고 음소거한 뒤 편집 SFX로 교체한다.
- 외부 영상 엔진 예비 경로는 두지 않는다. Flow의 가용성·크레딧·보안 제한이 제작을 막으면 해당 에피소드는 Flow blocker 상태로 남기며, 다른 공급자로 결과를 대신 만들지 않는다.

## 의미 결합형 사운드

- 생성 영상의 소리는 물·바람·공간음처럼 정확하고 깨끗할 때만 살리고, 아니면 클립을 음소거한 뒤 편집 SFX로 교체한다.
- 내레이션과 인물 대사는 생성 영상에 넣지 않고 ElevenLabs voice ID `wTGzPmtwk7nDNybbk0OL`의 clean TTS를 단일 원본으로 쓴다. 모델과 설정은 [references/voice-and-performance.md](references/voice-and-performance.md)의 고정 프로필을 사용하며 다른 보이스로 자동 대체하지 않는다.
- 장갑 스냅, 손그림 선, 숫자 틱, 반전 임팩트처럼 정합이 중요한 소리는 편집에서 넣는다.
- 큰 시각 타격의 효과음은 보통 2–3프레임 먼저 시작하고, 음악은 타격 때 4–8dB 덕킹한다.
- 모든 `sound_events[]`에는 실제 내레이션의 `trigger_phrase`와 `causal_purpose`가 있어야 한다.
- 소리를 매 샷에 채우지 않는다. 딜레마·질문 전환 직전의 짧은 정적도 설계된 이벤트다.

## 흐르듯 이어지는 운동 계약

- `계속 움직인다`는 모든 픽셀을 흔든다는 뜻이 아니다. 컷마다 시선이 따라갈 **주 운동 운반체** 하나를 정한다: 손, 뚜껑, 병, 기포, 레일, 카메라 이동, 빛 또는 입자 흐름.
- 앞 컷의 `continuity_out`과 다음 컷의 `continuity_in`은 같은 운반체·운동 방향·화면 위치·카메라 축 가운데 최소 둘을 공유한다.
- 의미가 바뀌어도 행동 매치, 물체 매치, 가림 전환, 휩팬, 벽 통과, 카메라 관성 이어받기 중 하나로 연결한다. 컷마다 새 방향으로 튀거나 정지 포스터로 리셋하지 않는다.
- 한 문장 안에서 정지 상태가 0.7초를 넘으면 의도적 홀드와 `causal_purpose`가 있어야 한다. 반전 직전·증거 판독을 제외한 죽은 정지는 실패다.
- 1.5–2.5초마다 새 시각 정보 또는 행동 변화가 생기되, 현재 문장의 의미와 장면 소유권을 벗어나면 안 된다.

## 조건부 쇼핑 수익화

- 모든 편에 상품을 억지로 붙이지 않는다. `commerce_route`는 `eligible`, `not_eligible`, `review_required` 중 하나다.
- 주제와 직접 관련된 실제 판매 상품이 있고, 정보 영상의 신뢰와 의료 안전을 해치지 않을 때만 `$run-coupang-partners-shorts-lab`으로 정확한 상품·옵션·판매자·가격·재고·배송·링크를 검증한다.
- 상품명·효능·사용 경험·가격을 추측하지 않는다. 의약품·응급의료 상품은 치료 보장이나 영상 속 역사적 사실을 구매 주장으로 바꾸지 않는다.
- 제휴 링크는 대본과 영상에 자동 삽입하지 않는다. 기본 위치는 설명 첫부분의 명확한 제휴 고지 뒤 링크와 승인된 고정 댓글이며, YouTube Shopping 상품 태그는 해당 채널에서 실제 자격과 상품을 확인한 경우만 사용한다.
- 정확한 상품·옵션·가격 확인 시각·주장·제휴 링크·고지·대상 채널이 잠기지 않으면 본편은 비제휴 상태로만 게시할 수 있고 쇼핑 라우트는 차단한다.

## 샷 밀도와 에셋 라우팅

- 40–80초: 24–36개 짧은 문장과 동일한 수의 TTS 의미 구간. Flow 생성은 10–18개의 8초 텍스트 투 비디오 멀티샷 원본으로 만든다.
- 생성형 영상: 인과적으로 붙은 2–3개 문장을 하나의 멀티샷 프롬프트로 묶고 문장별 좋은 구간을 수확한다.
- 프로그램식 모션: 치수·수치·라벨·절개·투명화·입자·전환을 영상 위에 합성한다. 정지 이미지를 최종 샷으로 대체하지 않는다.
- 실제 자료는 역사적 증거에 우선하고, 생성 이미지는 분위기와 재현임을 구분한다.
